# VBA第12课：VBA 工程保护和加密边界

## 这一节要做什么

前面我们已经把工具做成了加载宏，也讲了怎么让它对所有工作簿生效。

当你准备把工具发给别人用时，通常会遇到一个问题：

> VBA 代码能不能加密？能不能不让别人看到？

这一节就来讲 VBA 的工程保护。

先说结论：

> VBA 很难做到真正意义上的强加密。  
> 我们能做的是提高普通用户直接查看代码的门槛，而不是保证代码永远无法被破解。

## 本节你会学到

- 为什么 VBA 很难做到完美加密。
- 怎么给 VBA 工程设置查看密码。
- 工程密码能防住什么，防不住什么。
- 为什么有些工具可以解除 VBA 工程密码。
- 什么是“破坏工程查看结构”的保护方式。
- 发布工具时应该用什么心态看待代码保护。

## 为什么 VBA 很难真正加密

Excel 文件本质上可以看成一个压缩包。

我们之前已经多次看到：

```text
Excel 工作簿
  ↓
内部包含 XML、VBA 工程、资源文件等内容
```

VBA 代码就保存在这个工作簿结构里面。

只要你的功能还能正常运行，Excel 就必须能读取和执行这些代码。

这就意味着：

> 有技术能力的人，总有办法从文件中分析或提取 VBA 工程。

所以不要把 VBA 工程密码理解成银行保险柜。

它更像是：

```text
给普通用户加一道门槛
```

而不是：

```text
绝对无法破解的安全系统
```

## 第一种方式：设置 VBA 工程密码

最常见的做法，是给 VBA 工程设置查看密码。

操作步骤：

1. 打开启用宏的工作簿，例如 `final.xlsm`。
2. 按：

```text
Alt + F11
```

3. 在 VBA 编辑器中选中当前工程。
4. 点击：

```text
工具 → VBAProject 属性
```

5. 切换到：

```text
保护
```

6. 勾选：

```text
查看时锁定工程
```

7. 输入密码并确认。
8. 保存文件。
9. 关闭并重新打开工作簿。

重新打开后，如果再想展开 VBA 工程，就会要求输入密码。

## 工程密码适合防什么

VBA 工程密码适合防普通查看。

比如：

- 对方按 `Alt + F11` 后，不能直接展开代码；
- 普通用户不知道密码，就看不到模块内容；
- 同事只需要使用工具，不会误改你的代码；
- 发布给别人时，不至于一打开就看到全部源码。

它适合解决的问题是：

```text
不要让代码被普通用户随手看到或误改。
```

## 工程密码防不住什么

VBA 工程密码并不是强加密。

现实中存在一些工具，可以解除或绕过 VBA 工程密码。

也有人可以通过分析工作簿内部结构，对 VBA 工程进行处理。

所以不要认为：

```text
设置了工程密码 = 代码绝对安全
```

更准确的理解是：

```text
设置了工程密码 = 提高普通用户查看和修改代码的门槛
```

本课程不展开破解方法，也不建议用这些方法去处理别人的文件。

你只需要知道：

> VBA 工程密码不是不可破解的安全边界。

## 第二种方式：让工程不可直接查看

除了设置普通工程密码，还可以使用一些发布保护手段，让 VBA 工程在打开时显示为不可查看。

这种方式不是让用户输入密码，而是让工程在 VBA 编辑器里显示类似：

```text
工程不能查看
```

在本课程配套设计器里，可以通过加密或保护按钮生成一个受保护版本，例如：

```text
final.protected.xlsm
```

实际效果是：

- 文件仍然可以运行；
- 功能区和按钮仍然可用；
- 但普通用户在 VBA 编辑器中无法直接查看工程代码。

这种方式比普通工程密码更能挡住大部分普通用户。

## 这种保护是不是绝对安全

也不是。

如果对方非常懂 Excel 文件结构、VBA 工程结构和二进制文件处理，仍然可能想办法分析和还原。

只是这个门槛会比普通密码更高。

所以可以这样理解：

| 方式 | 能防住谁 | 防不住谁 |
| --- | --- | --- |
| 不保护 | 谁都能看 | 基本没有门槛 |
| VBA 工程密码 | 普通用户、误操作 | 会使用专门工具的人 |
| 工程不可查看保护 | 大部分普通用户 | 非常懂文件结构的人 |

实际发布时，做到第三层通常已经够用了。

## 不要迷信完美加密

这一点很重要。

哪怕你不用 VBA，而是用 C#、Python、JavaScript 或其他语言开发工具，也很难做到绝对无法分析。

例如：

- C# 编译后的 DLL 也可能被反编译；
- Python 打包成 exe 也可能被拆；
- 前端代码天然会暴露给浏览器；
- 即使看不到源码，别人也可以根据功能重新写一个类似工具。

现在 AI 写代码能力很强。

很多时候，代码本身不是最难复制的东西。

真正有价值的往往是：

- 你对业务场景的理解；
- 你知道用户需要什么；
- 你把工具做成了能用的流程；
- 你持续维护和迭代的能力；
- 你积累的模板、规则和交互设计。

所以保护代码是必要的，但不用过度焦虑。

## 推荐发布策略

如果只是自己用或团队内部用：

```text
设置 VBA 工程密码
```

如果准备发给更多人使用：

```text
先调试 final.xlsm
  ↓
确认功能没问题
  ↓
生成受保护版本
  ↓
另存或发布为 .xlam
  ↓
发给用户加载
```

也就是说：

- 开发版本保留可编辑代码；
- 发布版本做保护；
- 不要在唯一文件上直接做破坏式保护；
- 发布前先保留备份。

## 发布前要保留开发版本

这一点一定要注意。

如果你生成了不可查看的保护版本，后续自己也可能不方便再改代码。

所以建议至少保留两类文件：

```text
开发版：final.xlsm
发布版：final.protected.xlsm 或 final.xlam
```

开发版用于：

- 修改代码；
- 让 AI 继续注入；
- 调试功能；
- 更新版本。

发布版用于：

- 发给别人；
- 加载到 Excel；
- 避免普通用户直接查看代码。

## 常见问题

### 设置密码后为什么重新打开才生效

VBA 工程保护通常需要保存并重新打开文件后才会完整生效。

设置完密码后，建议：

```text
保存 → 关闭 → 重新打开 → 再测试
```

### 我忘记 VBA 工程密码怎么办

如果是自己的文件，最好的办法是从未加密的开发版恢复。

所以发布前一定要保留开发版。

不要只保留一个加密后的文件。

### 设置工程密码后功能还能运行吗

正常情况下可以。

工程密码只是限制别人查看 VBA 工程，不影响按钮和宏运行。

### 不可查看保护后功能还能运行吗

如果保护过程正确，功能仍然可以运行。

发布前一定要手动测试：

- 功能区是否正常显示；
- 按钮是否正常运行；
- 窗体是否正常打开；
- `.xlam` 加载是否正常。

### 代码被高手破解怎么办

这类风险无法完全消除。

你能做的是：

- 不在 VBA 里写敏感账号密码；
- 不把关键商业秘密硬编码在代码里；
- 发布前做基本保护；
- 保留开发版；
- 把重点放在业务能力和持续迭代上。

## 本节记住这五点

1. VBA 很难做到真正意义上的强加密。
2. 工程密码可以防普通查看，但不是绝对安全。
3. 工程不可查看保护能提高门槛，但也不是完美防护。
4. 发布前一定保留未保护的开发版。
5. 不要把全部价值寄托在“别人看不到代码”上。

## 课后练习

拿一个测试用的 `.xlsm` 文件练习工程保护。

完成标准：

1. 给 VBA 工程设置查看密码。
2. 保存、关闭、重新打开。
3. 按 `Alt + F11`，确认展开工程时需要密码。
4. 复制一份测试文件。
5. 使用设计器生成受保护版本。
6. 打开受保护版本，确认功能可以运行。
7. 确认 VBA 工程不能被普通方式直接查看。
8. 保留未保护的开发版，不要只保留受保护版本。
