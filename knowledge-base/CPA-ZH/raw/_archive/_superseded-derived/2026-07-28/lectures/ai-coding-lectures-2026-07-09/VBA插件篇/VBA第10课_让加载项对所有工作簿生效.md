# VBA第10课：让加载项对所有工作簿生效

## 这一节要做什么

前面我们一直在 `final.xlsm` 这个工作簿里测试功能区。

只要打开这个工作簿，就能看到我们做的自定义选项卡。

但是有一个问题：

> 如果新建一个普通 Excel 工作簿，这个自定义选项卡就没有了。

这一节要解决这个问题：

```text
把当前工具保存成 Excel 加载宏 .xlam
  ↓
在 Excel 加载项中启用它
  ↓
让这个功能区对所有工作簿生效
```

## 本节你会学到

- `.xlsm` 和 `.xlam` 的区别。
- 为什么普通工作簿只对自己生效。
- 怎么把工具另存为 Excel 加载宏。
- 怎么在 Excel 里加载 `.xlam` 文件。
- 为什么加载宏启用后，新建工作簿也能看到功能区。
- 后续迭代时应该改哪个文件、发布哪个文件。

## 当前问题：功能区只在当前工作簿里

打开 `final.xlsm`。

你可以看到我们做好的功能区选项卡，例如：

```text
智能工具
```

但是如果按：

```text
Ctrl + N
```

新建一个工作簿，你会发现新工作簿里没有这个选项卡。

原因是：

> `final.xlsm` 只是一个带宏代码的工作簿。  
> 它的功能区和 VBA 代码只跟这个工作簿绑定。

如果想让工具对所有 Excel 工作簿生效，就要把它变成加载宏。

## 什么是 .xlam

`.xlam` 是 Excel 加载宏文件。

可以简单理解为：

| 文件类型 | 用途 |
| --- | --- |
| `.xlsx` | 普通工作簿，不能保存宏 |
| `.xlsm` | 启用宏工作簿，宏只跟这个文件绑定 |
| `.xlam` | Excel 加载宏，可以加载到 Excel 全局环境 |

加载 `.xlam` 后，Excel 会在后台打开这个加载宏。

你不一定能在界面上看到这个工作簿，但它的功能区和 VBA 代码会一直可用。

## 第一步：把 final 另存为 .xlam

先关闭多余的 Excel 文件。

打开当前项目里的 `final.xlsm`。

选择：

```text
文件 → 另存为
```

文件类型选择：

```text
Excel 加载宏（*.xlam）
```

建议先把它保存到项目目录里，例如：

```text
workbooks/final.xlam
```

这样它和 `final.xlsm` 放在一起，后续更方便管理。

注意：

> 如果只是自己使用，也可以保存到 Excel 默认的 AddIns 目录。  
> 如果将来要发给别人使用，建议先保存到项目目录，再把 `.xlam` 文件发出去。

## 第二步：在 Excel 中启用加载宏

打开任意一个 Excel 工作簿。

进入：

```text
文件 → 选项 → 加载项
```

在底部选择：

```text
管理：Excel 加载项
```

点击：

```text
转到
```

在弹出的窗口中点击：

```text
浏览
```

选择刚才保存的：

```text
final.xlam
```

确认后，加载项列表里会出现这个加载宏。

勾选它，点击确定。

## 第三步：验证是否对所有工作簿生效

加载成功后，你应该能在当前 Excel 中看到自定义功能区。

接着按：

```text
Ctrl + N
```

新建一个工作簿。

如果新工作簿里也能看到同样的自定义选项卡，说明加载宏已经生效。

你还可以把 Excel 全部关闭，再重新打开。

如果重新打开 Excel 后，功能区仍然存在，说明这个加载宏已经被 Excel 记住了。

## 加载宏其实是在后台打开

加载 `.xlam` 后，Excel 会在后台打开这个加载宏文件。

按：

```text
Alt + F11
```

进入 VBA 编辑器。

你可能会看到类似：

```text
VBAProject (final.xlam)
VBAProject (Book1)
```

其中：

- `Book1` 是你当前正在编辑的普通工作簿；
- `final.xlam` 是后台加载的加载宏。

加载宏的代码就在 `final.xlam` 里。

只是它默认隐藏在后台，不像普通工作簿那样显示出来。

## 后续怎么迭代工具

建议记住这个流程：

```text
开发和调试：改 final.xlsm
  ↓
测试没问题
  ↓
另存为 final.xlam
  ↓
加载或发给别人使用
```

不要直接把 `.xlam` 当成主要开发文件。

更稳的方式是：

1. 继续在项目里的 `final.xlsm` 上调试。
2. 功能确认没问题后，再另存为 `.xlam`。
3. 把 `.xlam` 加载到 Excel，或发给其他人加载。

这样开发文件和发布文件就分开了。

## 发给别人怎么用

如果你要把工具发给同事，可以发这个文件：

```text
final.xlam
```

对方操作：

1. 打开 Excel。
2. 进入 `文件 → 选项 → 加载项`。
3. 选择 `Excel 加载项`，点击 `转到`。
4. 点击 `浏览`。
5. 选择你发给他的 `.xlam` 文件。
6. 勾选加载项，点击确定。

之后对方打开任意 Excel 工作簿，都可以看到这个工具。

## 常见问题

### 新建工作簿看不到功能区

检查 `.xlam` 是否已经在加载项里勾选。

路径：

```text
文件 → 选项 → 加载项 → Excel 加载项 → 转到
```

### 重新打开 Excel 后加载项不见了

可能是加载项路径变化，或者文件被移动了。

如果你把 `.xlam` 从原位置移动走，Excel 可能找不到它。

建议放在固定目录，不要频繁移动。

### 修改了 final.xlsm，加载项没有变化

因为 Excel 正在使用的是 `.xlam`。

你需要：

```text
重新把 final.xlsm 另存为 final.xlam
```

再重新加载或替换原来的 `.xlam`。

### Alt + F11 里看到 final.xlam 是正常的吗

正常。

这说明加载宏已经在后台打开了。

## 本节记住这四点

1. `.xlsm` 是启用宏工作簿，功能通常只跟这个文件绑定。
2. `.xlam` 是 Excel 加载宏，可以让工具对所有工作簿生效。
3. 加载宏启用后，Excel 会在后台打开它。
4. 后续开发建议改 `final.xlsm`，发布时再另存为 `.xlam`。

## 课后练习

把你当前项目里的 `final.xlsm` 发布成加载宏。

完成标准：

1. 另存为 `final.xlam`。
2. 在 Excel 加载项中浏览并勾选它。
3. 新建一个工作簿，确认能看到自定义功能区。
4. 关闭 Excel 后重新打开，确认加载项仍然存在。
5. 按 `Alt + F11`，观察后台的 `final.xlam` VBA 工程。
