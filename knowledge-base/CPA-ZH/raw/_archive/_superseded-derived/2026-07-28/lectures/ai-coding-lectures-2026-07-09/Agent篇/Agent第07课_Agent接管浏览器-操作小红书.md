# Agent第07课：Agent 接管浏览器，操作小红书

## 这一节要解决什么

前面几节课里，我们已经知道 Agent 可以读文件、写代码、整理课件、调用 Skill。

但很多真实工作并不只发生在本地文件夹里。

很多任务是在网页里完成的。

比如：

- 打开一个网站；
- 搜索信息；
- 点击页面按钮；
- 读取网页内容；
- 在已经登录的平台里查看资料；
- 总结搜索结果；
- 把重复操作整理成固定流程。

这节课要解决的问题就是：

```text
怎样让 Agent 接管我们当前正在使用的浏览器？
```

课程中使用的是 `Kimi WebBridge`。

它的作用是让 Agent 可以通过浏览器插件，操作当前浏览器里的页面。

官方入口：

[Kimi WebBridge - 让 AI Agent 可以使用浏览器](https://www.kimi.com/zh-cn/features/webbridge)

## 为什么要接管当前浏览器

很多 Agent 本身也有浏览器能力。

比如有些 Agent 会内置浏览器插件，有些会通过 Browser Use、MCP 或类似能力打开网页。

这类浏览器通常有两种形式。

第一种是无头浏览器。

它在后台运行，用户不一定能直接看到完整界面。

第二种是 Agent 自带的内置浏览器。

比如在某些 Agent 里，可以在侧边栏打开一个网页，Agent 可以读取页面、点击按钮、操作元素。

这些能力很好用。

但它们有一个问题：

```text
它们打开的，往往不是你平时正在使用的浏览器。
```

这就会带来一个很现实的问题：

```text
登录状态不能直接继承。
```

比如你平时已经在 Edge 或 Chrome 里登录了小红书。

但 Agent 如果打开的是一个新的浏览器环境，它可能不知道你已经登录过。

这样它就会卡在登录、扫码、验证码、风控这些环节。

而 Kimi WebBridge 这类插件的价值就在这里：

> 它让 Agent 操作的是你当前浏览器里的页面，因此可以继承你当前浏览器里的登录状态。

这对于小红书、公众号后台、飞书、企业微信、内部系统等网页任务非常重要。

## 这节课的整体流程

本节课的完整流程可以分成五步。

第一步，给浏览器安装 Kimi WebBridge 扩展。

第二步，给 Agent 安装对应的 WebBridge Skill。

第三步，测试 Agent 能不能通过插件打开网页、读取内容。

第四步，让 Agent 操作已经登录的小红书，搜索并总结信息。

第五步，把第一次操作中踩过的坑整理成 Skill，以后复用。

后面还演示了一个扩展用法：

```text
在手机微信里给 Agent 发任务，让电脑上的 Agent 去操作浏览器。
```

这相当于把 Agent 变成一个可以远程接任务的电脑助理。

## 第一步：安装浏览器扩展

要让 Agent 操作当前浏览器，先要在浏览器里安装 Kimi WebBridge 扩展。

课程中以 Edge 浏览器为例。

大致步骤是：

1. 打开 Kimi WebBridge 页面。
2. 选择手动安装。
3. 下载浏览器扩展包。
4. 打开 Edge 的扩展管理页面。
5. 打开开发者模式。
6. 把下载的扩展包拖入扩展页面。
7. 确认出现 `Kimi WebBridge`，并且处于启用状态。

如果使用的是 Chrome，操作逻辑类似。

关键是两点：

- 浏览器里要能看到 `Kimi WebBridge` 扩展；
- 这个扩展必须保持打开状态。

如果扩展没有启用，Agent 就无法通过它接管浏览器。

## 第二步：给 Agent 安装 WebBridge Skill

只在浏览器里安装扩展还不够。

浏览器扩展只是提供了一座桥。

Agent 还需要知道：

```text
怎么通过这座桥去操作浏览器。
```

所以第二步是把 Kimi WebBridge 提供的安装提示词复制到 Agent 里。

课程里用的是 WorkBuddy。

但这个步骤不是只能在 WorkBuddy 里做。

只要对应 Agent 支持安装 Skill 或类似能力，都可以尝试。

比如：

- WorkBuddy；
- Codex；
- Kimi；
- Cursor；
- Hermes；
- OpenClaw；
- OpenCode。

基本流程是：

1. 在 Kimi WebBridge 页面复制安装提示词。
2. 打开你正在使用的 Agent。
3. 新建任务或新建会话。
4. 粘贴这段提示词。
5. 让 Agent 按照说明安装对应能力。
6. 如果系统提示需要下载文件或申请权限，根据实际情况确认。

安装完成以后，Agent 里应该能看到类似 `Kimi WebBridge` 的能力。

后面就可以通过它操作当前浏览器。

## 第三步：先用普通网页测试

安装完成后，不要一上来就操作复杂网站。

可以先找一个普通网页测试。

课程里先让 Agent 打开自己的主页，并查找 AI 相关文章。

示例任务可以这样写：

```text
使用 Kimi WebBridge 打开 www.茶瓜子CPA.com，看一下有哪些 AI 相关的文章。
```

执行时需要注意：

- 浏览器里的 Kimi WebBridge 扩展要保持启用；
- 当前浏览器最好处于可见状态；
- 如果 Agent 申请操作权限，根据任务需要放行；
- 第一次打开某个网站时，Agent 可能会比较慢。

Agent 会尝试：

- 打开网页；
- 读取页面内容；
- 找到相关板块；
- 点击更多链接；
- 提取文章列表；
- 总结结果。

课程里最终找到了 11 篇 AI 相关文章。

这个测试的意义不在于文章本身。

而是确认：

```text
Agent 已经能通过 WebBridge 操作当前浏览器。
```

## 第一次操作网页为什么会慢

网页自动化不是每次都一步到位。

因为每个网站的结构都不一样。

有的网站按钮是普通按钮。

有的网站按钮其实是前端组件。

有的网站点击没反应，必须触发键盘事件。

有的网站内容要滚动后才加载。

有的网站登录状态、弹窗、遮罩层、验证码都会影响操作。

所以 Agent 第一次操作一个新网站时，经常会走弯路。

它可能需要反复尝试：

- 这个输入框在哪里；
- 这个按钮能不能点；
- 需要点击按钮还是按回车；
- 页面内容是否已经加载出来；
- 搜索结果在哪个区域；
- 哪些内容是真正的结果；
- 哪些内容只是广告或推荐。

这不是失败。

这更像是 Agent 在探索网页的操作规则。

## 关键思路：把踩过的坑写成 Skill

这节课最重要的不是“Agent 能打开网页”。

更重要的是这个方法：

```text
第一次让 Agent 探索流程，跑通后把经验整理成 Skill。
```

因为第一次操作某个网站时，Agent 可能会花很多时间试错。

但一旦流程跑通，就可以让它总结：

- 这个网站应该从哪个入口打开；
- 搜索框是什么元素；
- 直接点击搜索按钮是否有效；
- 需不需要按回车；
- 中文输入有没有问题；
- 结果区域怎么识别；
- 产物应该怎么总结；
- 哪些步骤容易失败；
- 下次应该避开哪些坑。

整理成 Skill 后，下次再做同类任务，就不用重新探索。

课程中把小红书搜索流程整理成了一个类似 `小红书-search` 的 Skill。

这个 Skill 记录了第一次操作小红书时发现的关键点。

比如：

- 先打开小红书；
- 搜索框应该如何定位；
- 直接点搜索按钮可能无效；
- 更稳定的方式是输入关键词后触发回车；
- 中文内容在 Windows 下可能出现字体或输入问题；
- 搜索结果需要从页面卡片中识别。

有了这个 Skill 后，Agent 第二次搜索其他博主时，就明显更直接。

## 第四步：操作已经登录的小红书

接下来课程演示了更有价值的场景：

```text
让 Agent 操作已经登录的小红书。
```

这也是当前浏览器接管的核心优势。

因为小红书这类网站通常需要登录。

如果 Agent 新开一个干净浏览器，里面没有登录状态，就会卡在登录环节。

但使用 Kimi WebBridge 时，Agent 操作的是你当前浏览器。

如果你已经在当前浏览器里登录了小红书，Agent 新打开的小红书页面也能继承这个登录状态。

课程里让 Agent 做的任务是：

```text
在小红书搜索“茶瓜子的休闲馆”相关信息，就在当前窗口操作。
```

Agent 执行过程大致是：

1. 打开小红书。
2. 继承当前浏览器的登录状态。
3. 找到搜索框。
4. 输入搜索关键词。
5. 执行搜索。
6. 阅读搜索结果。
7. 截图或整理产物。
8. 总结页面里的关键信息。

执行完成后，Agent 会把搜索结果整理出来。

比如：

- 搜索结果里出现了哪些内容；
- 哪些内容是本人发布的；
- 哪些内容是其他用户提到的；
- 核心要点是什么。

这类任务如果手工做，当然也能做。

但 Agent 的价值在于：

```text
它可以把搜索、点击、阅读、总结这些动作串成一个流程。
```

## 第五步：把小红书搜索流程沉淀下来

第一次搜索跑通后，不要急着结束。

更好的做法是让 Agent 立刻总结经验。

可以这样提要求：

```text
将上述流程整理成一个 Skill。之后我可能还要在小红书搜索其他博主。
```

Agent 会把刚才的操作经验写成一个可复用流程。

这个步骤很重要。

因为真正提高效率的不是让 Agent 做一次任务。

而是让它把一次任务变成以后可以复用的能力。

课程中创建好 `小红书-search` 后，又让 Agent 搜索另一个博主。

这一次它会自动加载刚才的 Skill。

执行时明显更顺：

- 直接创建新标签；
- 继承登录状态；
- 进入小红书；
- 填写搜索框；
- 用回车进入结果页；
- 读取博主文章和相关笔记；
- 输出结果产物。

这就是 Skill 的价值。

第一次踩坑，第二次复用。

## 这节课里的核心模式

可以把这一节课抽象成一个通用模式：

```text
连接工具
→ 让 Agent 操作真实网页
→ 观察第一次执行中的坑
→ 让 Agent 总结成 Skill
→ 下次同类任务直接复用
```

这个模式不只适用于小红书。

也可以用于：

- 公众号后台；
- 飞书文档；
- 企业微信后台；
- 内部业务系统；
- 数据查询平台；
- 招投标网站；
- 电商后台；
- 各类需要登录的网页系统。

只要任务具有重复性，就可以考虑沉淀成 Skill。

比如：

- 每周搜索某个平台上的行业信息；
- 定期查看某个账号的数据；
- 从网页后台导出报表；
- 在固定网站里检索关键词；
- 汇总某个主题下的最新笔记；
- 把搜索结果整理成表格或 Markdown。

## 手机发任务，电脑执行

课程最后还演示了 WorkBuddy 的助理功能。

它可以连接到手机微信。

绑定以后，你可以在手机上给 Agent 发任务。

但真正执行任务的地方，仍然是电脑上的 Agent。

比如在手机上发：

```text
在小红书搜索茶瓜子的休闲馆，看一下这个博主发了什么内容。
```

电脑上的 WorkBuddy 会收到任务。

然后它会复用之前安装好的：

- Kimi WebBridge；
- 小红书搜索 Skill；
- 当前浏览器登录状态。

最终还是在电脑浏览器里执行搜索和总结。

这个能力的意义是：

```text
你不一定非要坐在电脑前，才能让电脑上的 Agent 开始干活。
```

比如出门前电脑还开着。

你可以在手机上发一个任务，让电脑上的 Agent 继续处理。

当然，这类操作一定要注意权限和安全。

## 操作登录网站时要注意安全

让 Agent 接管当前浏览器很方便。

但也意味着它可以操作你已经登录的网站。

所以使用时要特别注意边界。

建议遵守几个原则。

第一，不要让 Agent 随意执行高风险操作。

比如：

- 发布内容；
- 删除内容；
- 修改账号资料；
- 更改密码；
- 支付；
- 下单；
- 转账；
- 给外部账号发送敏感信息。

第二，涉及最终提交的动作，最好自己确认。

可以让 Agent 准备草稿、整理内容、打开页面。

但真正点击“发布”“提交”“确认付款”之前，最好由人工检查。

第三，不要让 Agent 读取不该读取的隐私页面。

当前浏览器里可能有很多登录状态。

使用浏览器接管能力时，要知道 Agent 可能看见当前页面里的信息。

第四，遵守平台规则。

浏览器自动化适合提升自己的工作效率。

不要用它做批量骚扰、违规抓取、刷量、自动评论等违反平台规则的事情。

第五，第一次操作新网站时先用低风险任务测试。

比如先让它搜索、阅读、总结。

不要一上来就让它改数据或提交表单。

## 遇到问题时怎么排查

如果 Agent 没有成功操作浏览器，可以按下面几个点排查。

第一，浏览器扩展有没有安装成功。

在扩展页面里确认能看到 `Kimi WebBridge`。

第二，扩展有没有启用。

有时候扩展安装了，但没有打开。

第三，Agent 端 Skill 有没有安装好。

如果 Agent 不知道怎么调用 WebBridge，它也无法操作浏览器。

第四，当前浏览器是否可用。

有些页面加载慢、弹窗多、网络不稳定，都会影响操作。

第五，任务描述是否清楚。

尽量明确：

- 要在哪个网站操作；
- 搜索什么关键词；
- 是否在当前窗口操作；
- 最后要输出什么结果；
- 不要执行哪些高风险动作。

第六，模型能力是否足够。

复杂网页自动化对模型理解能力有要求。

如果自动模型效果不稳定，可以切换到更强的模型。

但更强的模型通常也更贵。

所以可以按任务重要程度选择。

## 这节课真正要学会的不是小红书

虽然课程用小红书做演示，但重点不是小红书。

重点是三个能力。

第一，让 Agent 操作当前浏览器。

第二，让 Agent 继承当前浏览器的登录状态。

第三，把第一次网页操作中踩过的坑沉淀成 Skill。

有了这三个能力，Agent 就不只是“会聊天”。

它可以开始进入真实网页环境，帮你处理很多原本需要手动点来点去的任务。

## 本节记住这些就够了

第一，Kimi WebBridge 可以让 Agent 通过浏览器扩展操作当前浏览器。

第二，当前浏览器最大的优势是可以继承已有登录状态。

第三，安装时分两步：浏览器端安装扩展，Agent 端安装对应 Skill。

第四，第一次操作新网站通常会慢，因为 Agent 要探索页面结构和操作规则。

第五，第一次跑通后，要让 Agent 把经验整理成 Skill。

第六，同一个网站的后续任务，可以复用这个 Skill，速度和稳定性都会更好。

第七，操作登录网站时要注意权限、安全和平台规则。

第八，手机发任务、电脑执行，本质上是让 Agent 远程接收指令，再在本地环境里干活。

## 课后练习

可以找一个低风险网站做练习。

比如自己的博客、公开资料网站、测试页面。

先让 Agent 完成一个简单任务：

```text
打开这个网站，找到和 AI 相关的文章，并整理标题列表。
```

然后继续要求：

```text
把刚才操作这个网站时遇到的关键步骤和注意事项整理成一个 Skill，方便以后复用。
```

最后再换一个关键词测试：

```text
按照刚才整理的 Skill，在这个网站里搜索 Excel 相关内容，并总结结果。
```

如果第二次明显比第一次顺，说明你已经理解了这一节的核心：

```text
Agent 的效率不是只靠模型变强，也靠把经验沉淀成可复用的流程。
```
