## 第0章：课程导引

### 如何使用本课程

这门总课只解决一个问题：**遇到一个复杂财务、审计或责任问题时，注册会计师应该怎样形成可复核的判断**。

“可复核”很重要。实务里真正有价值的判断，不是“我觉得可以”“以前项目这么做”“客户说没问题”，而是别人顺着你的底稿和逻辑往回看，能够看见：

- 你抓住了哪些关键事实；
- 你识别了哪些风险；
- 你适用了哪些规则；
- 你获取了哪些证据；
- 你为什么接受或不接受管理层判断；
- 你的结论会怎样影响财务报表、审计报告、法律责任或职业道德判断。

所以本课不是知识库目录，也不是准则编号表。CPA-ZH 知识库里有法律、会计准则、审计准则、政策、职业道德、独立性、案例和实务技能。本课把这些内容压缩成一个学习者能真正使用的判断框架。

后续课程会分别展开会计准则、审计准则、法律责任、职业道德、政策监管和综合案例。本课是所有后续课程的“操作系统”。学完本课后，你再学收入、金融工具、合并报表、持续经营、关键审计事项、独立性或证券服务责任，就不会只是在背知识点，而是在同一套判断链上补充工具。

### 学习方法建议

建议按三轮学习。

第一轮：读懂判断链。  
重点看第1章和第7章，掌握“事实 -> 风险 -> 规则 -> 证据 -> 判断 -> 结论”的表达方式。

第二轮：读懂交叉关系。  
重点看第2章、第4章、第5章、第6章，理解会计、审计、法律、职业道德不是四门互不相干的课，而是同一事项的不同层面。

第三轮：建立学习取舍。  
重点看第3章，理解为什么有些知识必须写得非常细，有些知识只适合作为背景或附录。CPA 考试能力等级在这里不是应试工具，而是帮助我们判断复杂度和学习深度的尺子。

学习时不要急着记术语。先把每章里的场景想明白，再回头看术语。专业术语只有放进场景里才有生命力。

## 第1章：执业判断的基本链条

### 学习目标

- [ ] 理解执业判断不是主观感觉，而是有证据支持的专业结论。
- [ ] 掌握“事实 -> 风险 -> 规则 -> 证据 -> 判断 -> 结论”的基本链条。
- [ ] 能区分事实、观点、证据和结论。
- [ ] 能把一个简单业务事项拆成会计问题、审计问题和责任问题。
- [ ] 能识别“直接下结论”的常见错误。

### 核心内容

#### 1. 什么是执业判断

执业判断可以先用一个很朴素的比喻理解：它不是“看菜单点菜”，而是“看病开方”。

菜单式思维是：看到收入就找收入准则，看到金融工具就找金融工具准则，看到证券服务责任就找证券法条款。这样只能找到材料，不能形成判断。

看病式思维是：先问症状、查体征、看化验结果，再判断病因，最后给治疗方案。注册会计师处理实务问题也一样：先看事实，再识别风险，再选择规则，再获取证据，最后形成结论。

**执业判断**，是注册会计师在准则、法律、职业道德和项目事实基础上，对会计处理、审计程序、证据充分性、报告结论或责任风险作出的专业判断。

它有三个特征：

第一，它不是纯主观意见。  
你可以有经验，但经验必须接受事实和证据检验。

第二，它不是机械套规则。  
准则和法律给出原则、条件和后果，但具体事实是否满足条件，需要判断。

第三，它必须能被复核。  
复核人不能只看到一句“经判断无重大异常”，而要看到判断过程。

#### 2. 基本链条：事实 -> 风险 -> 规则 -> 证据 -> 判断 -> 结论

执业判断最基础的链条是：

```text
事实 -> 风险 -> 规则 -> 证据 -> 判断 -> 结论
```

**事实**是已经发生或客观存在的交易、事项、条件和安排。  
例如合同条款、发货记录、验收记录、股权比例、董事会席位、资金流水、借款协议、回购条款、客户函证回函。

**风险**是这些事实可能导致的错报、违规、独立性威胁或报告风险。  
例如收入提前确认、金融资产分类错误、合并范围遗漏、关联方未披露、管理层凌驾、审计范围受限。

**规则**是判断所依据的准则、法律、政策或职业道德要求。  
例如收入五步法、控制三要素、预期信用损失模型、审计证据要求、证券服务机构勤勉尽责要求、独立性禁止性规定。

**证据**是支持或反驳判断的材料。  
例如合同、协议、会议纪要、外部函证、期后回款、估值报告、律师函、银行流水、管理层书面声明、治理层沟通记录。

**判断**是把事实、风险、规则和证据放在一起，评价条件是否满足。  
例如客户是否取得控制权，企业是否控制结构化主体，递延所得税资产是否很可能实现，审计证据是否充分适当。

**结论**是判断对财务报表、审计程序、报告和责任的影响。  
例如可以确认收入、应计提减值、应纳入合并范围、需要追加程序、需要调整报表、应发表保留意见或提示重大不确定性。

#### 3. 为什么不能从结论开始

很多实务错误都来自“先有结论，再找理由”。

例如，企业说：“这笔海外销售已经报关出口，所以可以确认收入。”  
这句话直接跳到了结论。正确做法应继续追问：

- 合同约定控制权什么时候转移？
- 报关只是出口手续，还是客户已经取得货权？
- 是否还需要安装、调试、验收？
- 尾款是否取决于最终客户接受？
- 是否存在退货、回购、补偿或重大售后义务？
- 期后是否发生退货或纠纷？

如果这些问题没有回答，仅凭“报关出口”就确认收入，判断链是断的。

再例如，管理层说：“我们持有 45% 股权，没有超过 50%，所以不用合并。”  
这也直接跳到了结论。正确做法要继续看：

- 其他股东是否分散；
- 企业是否有董事会多数席位；
- 是否通过合同主导相关活动；
- 是否享有可变回报；
- 是否能运用权力影响回报；
- 是否存在结构化主体或委托代理安排。

持股比例只是事实之一，不是控制判断的全部。

#### 4. 事实、证据、观点和结论的区别

这四个概念最容易混。

| 类型 | 含义 | 例子 | 常见错误 |
|---|---|---|---|
| 事实 | 客观发生或存在的事项 | 合同约定验收后付款；客户 1 月 5 日签署验收单 | 把管理层解释当事实 |
| 证据 | 用来支持或反驳判断的材料 | 合同、验收单、函证、银行回单 | 只收集支持管理层的证据 |
| 观点 | 某一方对事实的解释 | 管理层认为验收只是形式 | 把观点当结论 |
| 结论 | 专业判断的最终结果 | 12 月 31 日尚未转移控制权，不应确认收入 | 没有证据链就下结论 |

底稿里最怕出现这种句子：“经访谈，管理层认为不存在问题，因此项目组认为无异常。”  
这句话几乎没有专业判断。访谈可以是证据来源之一，但管理层观点不能替代项目组判断。

#### 5. 一个简单例子：从预收款到收入判断

场景：甲公司 12 月收到客户 100 万元，合同约定次年 1 月交付设备。

错误思维：钱收到了，所以确认收入。

判断链应这样走：

```text
事实：12 月收款，1 月交付设备。
风险：提前确认收入，导致本年收入和利润虚增。
规则：收入确认核心是客户取得商品控制权，不是收款。
证据：合同、收款凭证、发货记录、验收安排、期后交付资料。
判断：12 月客户尚未取得设备控制权，企业仍负有交付义务。
结论：12 月通常确认合同负债，不确认收入；1 月控制权转移时再确认收入。
```

这个例子很简单，但方法适用于复杂问题。长投、合并、金融工具、持续经营、关键审计事项、证券责任，本质上都要走类似链条。

#### 6. 判断链断在哪里，风险就藏在哪里

实务中常见的断点有六类：

第一，事实不完整。  
只拿主合同，不拿补充协议；只看发货，不看验收；只看股权比例，不看董事会安排。

第二，风险没识别。  
看到合同就确认收入，没想到舞弊风险和截止风险；看到估值报告就接受公允价值，没想到管理层偏向。

第三，规则套错。  
把销售退回当普通销售，把合同资产当应收账款，把保护性权利当控制权。

第四，证据不足。  
只有管理层说明，没有外部证据；只有内部测算，没有参数来源；只有律师口头意见，没有律师函。

第五，判断没有解释。  
底稿只写结论，不写为什么满足或不满足条件。

第六，结论没有落地。  
识别出重大不确定性，但没有考虑披露和审计报告影响；发现收入错报风险，但没有调整程序。

### 记忆辅助

#### 判断链对比表

| 环节 | 解决的问题 | 典型材料 | 如果缺失会怎样 |
|---|---|---|---|
| 事实 | 发生了什么 | 合同、记录、流水、会议纪要 | 判断对象不清 |
| 风险 | 可能错在哪里 | 风险评估、异常分析、行业背景 | 程序没有方向 |
| 规则 | 应按什么标准判断 | 会计准则、审计准则、法律、职业道德 | 结论没有依据 |
| 证据 | 用什么支持判断 | 函证、验收、估值、律师函、期后资料 | 判断站不住 |
| 判断 | 条件是否满足 | 技术备忘、底稿分析 | 复核无法理解 |
| 结论 | 对报表和报告有什么影响 | 调整分录、披露、报告意见 | 工作没有收口 |

#### 口诀

先看事实，再找风险；  
规则定边界，证据撑判断；  
结论要落报表，底稿能复盘。

#### 易错警示卡

| 错误说法 | 问题 | 应改成 |
|---|---|---|
| 客户说没问题，所以可以确认 | 客户说法只是证据之一 | 结合合同、履约、验收、回款和期后情况判断 |
| 持股没过半，所以不控制 | 控制不只看比例 | 看权力、可变回报、运用权力影响回报 |
| 有估值报告，所以公允价值可靠 | 估值报告也要评价 | 看模型、参数、专家胜任能力和敏感性 |
| 法条规定了责任，所以事务所有责任 | 责任需要事实和因果 | 看是否未勤勉尽责、是否有重大错报、是否有证据抗辩 |

### 本章小结

1. 执业判断不是主观感觉，而是事实、规则和证据支撑下的专业结论。
2. 基本判断链是事实 -> 风险 -> 规则 -> 证据 -> 判断 -> 结论。
3. 管理层观点不能替代项目组判断。
4. 持股比例、收款、开票、报关、估值报告都只是事实或证据，不自动等于结论。
5. 底稿要让复核人看见判断过程，而不是只看见一句结论。

## 第2章：会计判断、审计判断、法律责任和职业道德的关系

### 学习目标

- [ ] 理解会计判断、审计判断、法律责任和职业道德分别解决什么问题。
- [ ] 能识别同一事项在四个层面的不同影响。
- [ ] 能避免“只懂会计处理，不看审计证据和责任后果”的学习误区。
- [ ] 能用四层框架分析收入、合并、关联方等常见事项。
- [ ] 理解职业道德和独立性是承接、执行和签发的前置约束。

### 核心内容

#### 1. 四个层面各管什么

同一件事，可以同时是会计问题、审计问题、法律问题和职业道德问题。

以收入为例：

- 会计判断问：是否满足收入确认条件，金额是多少，列报在哪里，披露什么；
- 审计判断问：收入是否存在重大错报风险，程序如何设计，证据是否充分适当；
- 法律责任问：如果收入虚假，管理层、公司、信息披露义务人、证券服务机构可能承担什么责任；
- 职业道德问：注册会计师是否保持客观、独立和职业怀疑，是否受到收费、关系或压力影响。

如果只学会计，你可能会写出正确分录，但不知道证据是否够。  
如果只学审计，你可能会列程序，但不知道错报到底错在哪里。  
如果只学法律，你可能会背责任条款，但不知道责任如何从具体错报发生。  
如果忽视职业道德，你可能程序做得像样，却在承接、独立性或签发前已经越过底线。

#### 2. 会计判断：业务事实如何进入财务报表

会计判断的核心问题是：**这个业务事实应如何被财务报表表达**。

它通常拆成四个动作：

| 动作 | 问题 | 例子 |
|---|---|---|
| 确认 | 是否进入报表 | 是否确认收入、预计负债、递延所得税资产 |
| 计量 | 金额是多少 | 按摊余成本、公允价值、可收回金额还是预计损失 |
| 列报 | 放在哪个项目 | 合同资产还是应收账款，金融负债还是权益工具 |
| 披露 | 附注说明什么 | 重大判断、估计不确定性、风险暴露、关联方关系 |

会计判断不是“做分录”。分录只是结论的技术表达。真正困难的是条件判断。

例如，售后回购安排下是否确认收入，关键不是借贷方向，而是客户是否取得控制权、回购条款是否限制客户使用商品、客户是否有重大经济动因要求回购。

#### 3. 审计判断：证据能否支撑报表结论

审计判断的核心问题是：**注册会计师能否获得充分、适当的证据，对财务报表整体是否不存在重大错报获取合理保证**。

审计判断不是把会计结论抄一遍。它要继续问：

- 管理层作出这个会计判断的依据是什么；
- 这个判断涉及哪些认定；
- 哪些事实可能导致重大错报；
- 证据来自内部还是外部；
- 证据是否直接；
- 是否存在相互矛盾的证据；
- 是否需要专家；
- 是否需要扩大样本或执行替代程序；
- 证据不足是否影响审计意见。

例如，管理层认为商誉没有减值。会计上要看资产组、可收回金额、关键假设；审计上还要看预算可靠性、折现率来源、增长率合理性、历史预测偏差、敏感性分析、专家工作和披露充分性。

#### 4. 法律责任：谁对什么后果负责

法律责任的核心问题是：**当财务报告、审计报告或信息披露出现问题时，谁基于什么义务承担什么责任**。

CPA-ZH 课程中的法律不应写成条文背诵，而要写成责任链：

```text
责任主体 -> 法定义务 -> 违反方式 -> 后果 -> 注册会计师应对
```

例如，证券服务责任不是一句“证券服务机构应勤勉尽责”就结束。要继续讲：

- 服务对象是不是证券发行或信息披露；
- 财务信息是否存在虚假记载、误导性陈述或重大遗漏；
- 会计师事务所出具的文件是否被使用；
- 项目组是否执行了必要程序；
- 底稿能否证明勤勉尽责；
- 如果不能证明，是否存在赔偿或监管责任风险。

#### 5. 职业道德和独立性：能不能做、怎样做、能不能签

职业道德和独立性不是软约束，而是底线判断。

它们贯穿三个时点：

第一，承接前。  
要判断客户诚信、业务风险、独立性、专业胜任能力和资源是否允许承接。

第二，执行中。  
要持续识别不利影响，例如管理层压力、收费依赖、长期关系、自我评价威胁、利益冲突。

第三，签发前。  
要判断不利影响是否已经消除或降低至可接受水平，证据是否足以支撑报告，是否存在不应继续业务的情况。

例如，一个项目收入占事务所收入比例过高，客户又持续施压要求接受收入提前确认。这里不仅是收入审计问题，也是独立性和职业道德问题。项目组如果只讨论收入准则而不讨论压力和经济利益威胁，判断是不完整的。

#### 6. 四层框架如何用于一个事项

以关联方资金占用为例：

```text
会计层面：是否构成关联方交易或余额，是否准确列报和披露。
审计层面：关联方识别是否完整，资金流水是否异常，函证和访谈是否支持。
法律层面：是否涉及控股股东、实际控制人侵占公司利益，是否构成信息披露重大遗漏。
职业道德层面：项目组是否受到客户压力，是否保持职业怀疑，是否因长期关系弱化判断。
```

如果只看会计层面，可能只关注科目重分类；如果四层一起看，就能看到资金流、控制关系、披露责任和审计证据之间的关系。

### 记忆辅助

#### 四层判断对比表

| 层面 | 核心问题 | 典型输出 | 常见误区 |
|---|---|---|---|
| 会计判断 | 业务事实如何进报表 | 会计处理、列报、披露 | 只背分录 |
| 审计判断 | 证据是否支撑报表 | 程序、底稿、审计结论 | 只列程序不看风险 |
| 法律责任 | 谁对后果负责 | 责任分析、风险提示 | 只背法条 |
| 职业道德 | 能不能做、是否客观独立 | 承接判断、防范措施 | 当成软要求 |

#### 一句话记忆

会计看报表表达，审计看证据支撑，法律看责任后果，道德看底线能不能守住。

#### 思维地图

```text
一个实务事项
  -> 会计：确认、计量、列报、披露
  -> 审计：风险、程序、证据、报告
  -> 法律：主体、义务、违反、责任
  -> 道德：诚信、客观、胜任、独立
```

### 本章小结

1. 同一事项通常同时具有会计、审计、法律和职业道德含义。
2. 会计判断解决报表表达问题。
3. 审计判断解决证据是否足以支撑报表结论的问题。
4. 法律责任解决责任主体、义务违反和后果问题。
5. 职业道德和独立性决定能不能承接、怎样执行、能不能签发。

## 第3章：知识分级和学习深度

### 学习目标

- [ ] 理解本课程为什么使用 P0/P1/P2/P3 分级。
- [ ] 理解 CPA 考试能力等级在本课程中只用于校准深度。
- [ ] 能判断一个知识点为什么需要详细讲，或为什么只放附录。
- [ ] 能识别“覆盖很多但都很浅”的学习陷阱。
- [ ] 能为后续课程建立合理学习预期。

### 核心内容

#### 1. 为什么必须分级

CPA-ZH 知识库内容很多。如果不分级，课程会变成两种坏结果。

第一种坏结果是目录化：每个法律、准则、政策都提一句，学习者看完知道很多名字，但不会判断。

第二种坏结果是平均用力：收入确认和下载状态占同样篇幅，金融工具估值和索引维护写得一样长。这样会浪费学习精力，也会让真正高风险知识讲不深。

所以课程必须分级。分级的目的不是删除知识，而是决定知识在课程中的位置和深度。

#### 2. P0/P1/P2/P3 的含义

| 分级 | 含义 | 课程写法 | 例子 |
|---|---|---|---|
| P0 | 核心判断能力 | 必须详细讲，有案例、有证据、有错法、有练习 | 收入、金融工具、合并范围、会计估计、审计证据 |
| P1 | 重要系统知识 | 系统讲清，连接实务场景 | 租赁、政府补助、或有事项、质量管理 |
| P2 | 支撑背景知识 | 作为基础或附录讲 | 基本准则、三方关系、行业历史 |
| P3 | 维护索引材料 | 不进入正文 | raw 路径、下载清单、未映射资料 |

P0 的判断标准是：它是否经常出现在复杂交易中，是否可能导致重大错报，是否需要审计证据支撑，是否可能引发报告或责任风险。

例如，收入确认必须是 P0。因为收入直接影响利润，舞弊动机强，涉及合同、履约、控制权、截止、退货、函证和证券披露。

下载状态通常是 P3。它对知识库维护有用，但不是学习者执业判断的核心内容。

#### 3. CPA 考试能力等级如何使用

本课程不是 CPA 考试课程，但 CPA 考试大纲的能力等级有参考价值。

原因是：CPA 考试能力等级往往反映一个知识点是否需要综合运用。等级越高，通常说明它不仅要理解概念，还要能处理复杂职业场景。

但是本课程不会把“考试高频”直接等同于“课程目标”。课程目标仍然是执业判断。CPA 考试只提供一个外部校准信号：

```text
如果某知识点在考试中要求综合运用，且 CPA-ZH 知识库中有充分支撑，
那么它在本课程中通常应提高讲解深度。
```

反过来，如果某知识点考试重要，但 CPA-ZH 当前缺少资料支撑，例如完整税法、财务成本管理、战略管理，本课程不会硬写成完整课程，而会标为知识库缺口或仅讲交叉部分。

#### 4. 深度不是篇幅，而是判断颗粒度

详细不是把文字写长。真正的详细，是判断颗粒度足够细。

以“收入确认”为例，浅写法是：

```text
收入确认采用五步法，应在履约义务满足时确认收入。
```

这句话没错，但没法学习。

详细写法要继续讲：

- 什么是合同；
- 合同没有商业实质怎么办；
- 履约义务如何拆分；
- 控制权转移有哪些证据；
- 时点和时段如何区分；
- 可变对价为什么不能确认太满；
- 合同资产和应收账款差别在哪里；
- 售后回购如何判断；
- 期末收入截止如何审计；
- 错误确认会怎样影响报告和责任。

这才叫详细。

#### 5. 分级如何指导后续学习

后续课程中，你可以这样分配精力：

- P0：精读、做题、复盘案例，必须能自己写判断过程；
- P1：系统学习，至少能识别场景和常见风险；
- P2：理解概念，用来支撑主干知识；
- P3：知道存在，不进入学习主线。

如果学习时间有限，先学 P0。  
如果要做项目实务，P0 和 P1 都要掌握。  
如果要维护知识库或做课程扩展，再处理 P2 和 P3。

### 记忆辅助

#### 分级对比表

| 问题 | P0 | P1 | P2 | P3 |
|---|---|---|---|---|
| 是否进入正文 | 必须 | 必须 | 适度 | 通常不进入 |
| 是否详细讲案例 | 必须 | 视情况 | 少量 | 不需要 |
| 是否需要审计证据 | 必须 | 通常需要 | 作为背景 | 不需要 |
| 是否影响报告或责任 | 常见 | 可能 | 间接 | 很少 |
| 学习目标 | 会判断 | 会应用 | 会理解 | 会查找 |

#### 口诀

P0 要会断，P1 要会用；  
P2 打基础，P3 留后台。

### 本章小结

1. 分级是为了防止课程变成目录，也防止平均用力。
2. P0 是核心判断能力，必须写得很细。
3. CPA 考试能力等级只用于校准知识复杂度，不改变课程目标。
4. 详细不是文字长，而是判断颗粒度细。
5. 学习时先抓 P0，再扩 P1，P2/P3 服务主线。

## 第4章：财务报表项目不是孤立科目

### 学习目标

- [ ] 理解财务报表项目之间存在联动关系。
- [ ] 能识别收入、金融工具、合并、减值、所得税等事项之间的交叉影响。
- [ ] 能避免“一个科目一个结论”的碎片化学习。
- [ ] 能用交易链和报表链分析复杂事项。
- [ ] 能理解为什么综合案例常常跨越多个准则。

### 核心内容

#### 1. 报表不是科目仓库，而是经济活动的表达

初学会计时，我们容易把报表项目当成一个个孤立格子：收入在利润表，存货在资产负债表，应收账款在资产负债表，所得税在利润表，合并报表在另一个专题。

但实务中，一个交易会同时影响多个项目。

例如，企业销售定制设备：

- 是否确认收入影响营业收入；
- 是否结转成本影响营业成本和存货；
- 是否形成应收账款或合同资产影响资产列报；
- 是否存在退货或质保影响预计负债；
- 是否存在重大融资成分影响利息收入或费用；
- 是否有所得税差异影响所得税费用和递延所得税；
- 如果客户是关联方，还影响关联方披露；
- 如果收入重大且判断复杂，还可能成为关键审计事项。

所以课程不能把每个准则割裂地学。真正的学习方式是：以业务事实为起点，看它穿过哪些报表项目和规则。

#### 2. 交易链：从业务安排到报表结果

交易链是一种分析方法。它不是看某一个会计科目，而是看交易从发生到报表表达的全过程。

以“销售商品并提供安装服务”为例：

```text
合同签订
  -> 收取预付款
  -> 发出商品
  -> 安装调试
  -> 客户验收
  -> 开票结算
  -> 回款
  -> 期后维护或退货
```

每个节点都可能影响会计判断：

- 收取预付款时通常不是收入，而可能是合同负债；
- 发出商品不一定意味着控制权转移；
- 安装调试可能是单独履约义务，也可能与设备构成一项履约义务；
- 验收可能是实质条件，也可能只是例行程序；
- 回款可以支持商业真实性，但不自动证明收入确认时点；
- 期后退货可能反映收入估计不当。

#### 3. 报表链：一个判断如何影响多个报表项目

报表链关注一个判断结论对多个报表项目的影响。

例如，金融资产分类错误：

- 分类为摊余成本还是 FVTPL，会影响资产账面价值；
- 公允价值变动进损益还是其他综合收益，会影响利润和权益；
- 预期信用损失计提影响减值损失和资产减值准备；
- 相关风险披露影响附注；
- 如果金融工具重大且估值复杂，影响关键审计事项；
- 如果公开披露不充分，可能涉及证券信息披露责任。

一个错误分类，不只是科目放错，而可能改变利润、权益、风险披露和审计报告。

#### 4. 常见交叉关系

| 起点事项 | 可能联动的知识 | 判断重点 |
|---|---|---|
| 收入确认 | 合同资产、应收账款、预期信用损失、所得税、舞弊风险 | 控制权转移和证据链 |
| 金融工具 | 公允价值、减值、权益工具、列报披露、专家工作 | 分类和估值 |
| 合并范围 | 长投、控制、关联方、集团审计、证券披露 | 是否控制及是否遗漏主体 |
| 商誉减值 | 企业合并、资产组、估值、专家、关键审计事项 | 可收回金额和关键假设 |
| 关联方资金占用 | 往来款、减值、披露、公司法、证券法 | 完整性和资金实质 |
| 持续经营 | 借款、流动性、诉讼、融资计划、审计报告 | 重大不确定性 |

#### 5. 为什么综合案例最能检验学习效果

综合案例不会告诉你“本题考收入准则”。它会给你一堆事实：合同、补充协议、发货、验收、回款、关联关系、管理层解释、期后退货、律师意见、估值报告。

你的任务是判断哪些事实重要，哪些规则适用，哪些证据不足，哪些结论会影响报表和报告。

这正是 CPA-ZH 课程要训练的能力。不是把所有知识点都背下来，而是在复杂事实中找到判断主线。

### 记忆辅助

#### 交易链与报表链对比表

| 方法 | 看什么 | 适合解决什么问题 |
|---|---|---|
| 交易链 | 业务从发生到收口的过程 | 判断控制权转移、履约、回款、期后事项 |
| 报表链 | 一个判断影响哪些项目 | 判断错报扩散、列报披露、报告影响 |

#### 常见联动图

```text
收入确认
  -> 应收账款 / 合同资产
  -> 预期信用损失
  -> 所得税
  -> 舞弊风险
  -> 函证和截止测试
  -> 信息披露责任
```

#### 易错警示卡

| 错误学习法 | 后果 | 正确学习法 |
|---|---|---|
| 一个准则一个孤岛 | 综合案例不会用 | 从业务事实看规则联动 |
| 只看分录 | 忽略证据和披露 | 同时看确认、计量、列报、披露 |
| 只看当期入账 | 忽略期后事项 | 把交易链拉到期后 |

### 本章小结

1. 财务报表项目不是孤立科目，而是经济活动的联动表达。
2. 交易链帮助我们看业务过程。
3. 报表链帮助我们看一个判断影响哪些报表项目。
4. 收入、金融工具、合并、减值、所得税、关联方等专题经常交叉。
5. 综合案例训练的是从复杂事实中抓主线的能力。

### 知识检测

#### 一、判断题

1. [ ] 一个收入判断错误只会影响营业收入，不会影响其他项目。  
2. [ ] 交易链可以帮助判断收入确认时点。  
3. [ ] 金融资产分类可能影响损益、其他综合收益和披露。  
4. [ ] 综合案例通常只涉及一个准则。  
5. [ ] 报表链有助于识别错报扩散影响。

## 第5章：审计不是程序清单

### 学习目标

- [ ] 理解审计程序必须由风险驱动。
- [ ] 能区分“做了程序”和“程序有效回应风险”。
- [ ] 能理解审计证据的充分性和适当性。
- [ ] 能识别函证、监盘、分析程序和抽样的适用边界。
- [ ] 能把重大错报风险、程序设计、证据评价和报告结论连起来。

### 核心内容

#### 1. 为什么不能把审计当程序清单

审计程序清单很容易给人安全感。比如收入审计：抽合同、查发票、看发货单、做截止、函证。看起来很完整。

但如果不知道风险是什么，程序可能只是形式。

例如，收入风险是“客户尚未验收但提前确认”。如果项目组只检查发票和发货单，没有检查验收条件和客户接受证据，程序就没有回应核心风险。

再例如，金融工具风险是“第三层次公允价值估值偏高”。如果项目组只取得估值报告，没有评价模型和参数，也没有做敏感性分析，程序也没有回应核心风险。

审计不是把清单做完，而是用程序取得能回应风险的证据。

#### 2. 风险驱动审计的基本逻辑

风险导向审计可以理解为：

```text
识别风险 -> 评估风险 -> 设计程序 -> 获取证据 -> 评价证据 -> 形成结论
```

这里的关键是“对应关系”。

| 风险 | 有效程序应关注 |
|---|---|
| 收入提前确认 | 控制权转移、验收、期后退货、截止 |
| 应收账款不存在 | 函证、期后回款、客户沟通、交易真实性 |
| 存货不存在 | 监盘、盘点控制、抽盘、存货移动 |
| 商誉减值不足 | 资产组、预测、折现率、增长率、敏感性 |
| 关联方遗漏 | 股权结构、资金流水、异常交易、工商信息 |
| 持续经营不确定性 | 现金流预测、融资协议、债务到期、违约条款 |

程序是否有效，不看它是不是常见程序，而看它是否回应了具体风险。

#### 3. 审计证据：充分性和适当性

审计证据有两个维度：充分性和适当性。

**充分性**是数量。风险越高，需要的证据通常越多。

**适当性**是质量，包括相关性和可靠性。证据必须与风险相关，也必须足够可靠。

外部独立来源的证据通常比内部证据更可靠；注册会计师直接获取的证据通常比间接证据更可靠；原始文件通常比复印件或截图更可靠。但这些只是一般原则，具体仍要看场景。

例如，客户回函确认应收账款余额存在，但如果收入确认的风险是“虽然发货但尚未验收”，函证余额不一定足以证明收入确认时点正确。证据可靠不等于证据相关。

#### 4. 常见程序的边界

**函证**适合验证外部单位确认的信息，如应收账款余额、银行存款、借款、往来款。但函证不是万能。回函可以证明余额存在，不一定证明收入确认条件满足。

**监盘**适合验证存货存在和状态，但不能单独证明存货所有权、计价或跌价准备充分。

**分析程序**适合识别异常关系和趋势，但如果风险很高，通常不能单独作为充分证据。

**抽样**适合从总体中选取样本测试，但样本设计必须与测试目标匹配。抽样不是“随便抽几笔看看”。

**管理层书面声明**是必要证据之一，但不能替代其他审计证据。

#### 5. 证据矛盾时怎么办

实务中经常出现证据冲突：

- 合同约定验收后控制权转移，但企业按发货确认收入；
- 客户回函确认余额，但期后大量退货；
- 管理层预测乐观，但历史预测长期偏差；
- 律师口头说风险不大，但未出具正式律师函；
- 估值报告支持公允价值，但关键参数缺少市场依据。

遇到证据冲突，不能选择性采纳对客户有利的证据。应追加程序，评价矛盾原因，并考虑是否存在管理层偏向或舞弊风险。

### 记忆辅助

#### 风险和程序匹配表

| 审计风险 | 程序方向 | 证据例子 |
|---|---|---|
| 收入截止错误 | 查期末前后控制权转移 | 合同、发货、签收、验收、期后退货 |
| 应收账款虚增 | 外部确认和期后回款 | 函证、银行回单、客户访谈 |
| 估值偏高 | 评价模型和参数 | 估值报告、市场数据、敏感性分析 |
| 关联方遗漏 | 查关系和资金流 | 工商信息、股权图、银行流水 |
| 持续经营风险 | 查现金流和融资 | 预算、借款协议、债务到期表 |

#### 口诀

风险定方向，程序找证据；  
证据看相关，也看可靠；  
清单做完不算完，风险回应才算数。

### 本章小结

1. 审计不是程序清单，而是风险驱动的证据获取过程。
2. 程序有效性取决于是否回应具体风险。
3. 审计证据要同时看充分性和适当性。
4. 常见程序都有边界，不能机械套用。
5. 证据冲突时应追加程序并评价管理层偏向或舞弊风险。

### 知识检测

#### 一、判断题

1. [ ] 只要执行了标准审计程序清单，就一定能应对所有风险。  
2. [ ] 函证余额存在不一定证明收入确认时点正确。  
3. [ ] 管理层书面声明可以替代其他必要审计证据。  
4. [ ] 证据的适当性包括相关性和可靠性。  
5. [ ] 风险越高，通常需要更有力的证据。

#### 二、单选题

1. 审计程序设计最应首先回应的是：  
   A. 底稿格式  
   B. 重大错报风险

   D. 去年模板  

2. 如果商誉减值风险很高，最不充分的做法是：  
   A. 评价现金流预测  
   B. 评价折现率和增长率  
   C. 取得估值报告后不再复核  
   D. 做敏感性分析  

#### 三、情景判断

项目组对大额应收账款取得了客户回函，但发现对应收入在期后大量退货。项目组能否仅凭回函认为收入无异常？为什么？

## 第6章：责任不是法条背诵

### 学习目标

- [ ] 理解法律责任学习应围绕责任主体、义务、违反方式和后果展开。
- [ ] 能区分管理层责任、注册会计师责任和证券服务机构责任。
- [ ] 能理解勤勉尽责为什么要靠底稿证据证明。
- [ ] 能把会计错报、审计证据和法律责任连接起来。
- [ ] 能避免“背法条但不会用”的学习误区。

### 核心内容

#### 1. 法律责任的正确学习方式

法律条文是规则来源，但课程不能停在条文本身。

学习法律责任时，要问五个问题：

```text
谁是责任主体？
他负有什么义务？
违反义务的事实是什么？
造成或可能造成什么后果？
注册会计师如何识别、应对和留痕？
```

这比背条文更接近实务。

例如，“信息披露应真实、准确、完整”这句话很重要，但还不够。你还要能判断：

- 哪些财务信息进入信息披露文件；
- 收入、减值、关联方、持续经营是否存在重大遗漏或虚假记载；
- 管理层和治理层是否提供完整资料；
- 会计师事务所是否对重大事项执行了必要程序；
- 底稿能否证明项目组勤勉尽责。

#### 2. 责任主体

CPA-ZH 课程中常见责任主体包括：

| 责任主体 | 典型责任 |
|---|---|
| 单位负责人 | 对会计资料真实性、完整性负责 |
| 管理层 | 编制财务报表，选择和运用会计政策，作出会计估计 |
| 治理层 | 监督财务报告过程和审计过程 |
| 公司、发行人、信息披露义务人 | 依法披露真实、准确、完整的信息 |
| 注册会计师 | 按准则执业，获取充分适当证据，发表恰当意见 |
| 会计师事务所 | 建立质量管理体系，对业务质量承担责任 |
| 证券服务机构 | 在证券业务中勤勉尽责，对所出具文件负责 |

责任主体不同，义务不同。不能把管理层责任推给注册会计师，也不能用“这是管理层责任”掩盖注册会计师未勤勉尽责的问题。

#### 3. 管理层责任和注册会计师责任的边界

管理层负责财务报表。注册会计师负责按照审计准则执行审计并发表意见。

这意味着：

- 管理层不能说“审计师没发现，所以我不负责”；
- 注册会计师也不能说“报表是管理层编的，所以我不需要执行充分程序”。

两者责任不同，但会在同一个错报事项上交汇。

例如，企业虚构收入。管理层可能因编制虚假财务报告或信息披露违法承担责任。注册会计师如果未对收入舞弊风险保持职业怀疑，未执行必要程序，底稿不能证明勤勉尽责，也可能承担执业责任或证券服务责任。

#### 4. 勤勉尽责如何证明

勤勉尽责不是一句态度声明，而是底稿事实。

要证明勤勉尽责，至少要能看到：

- 项目组识别了重大风险；
- 设计了与风险匹配的程序；
- 获取了充分适当的证据；
- 对矛盾证据作出评价；
- 对重大判断形成技术备忘；
- 与管理层和治理层进行了必要沟通；
- 对报告影响作出恰当判断；
- 复核和质量控制留痕完整。

如果底稿只有形式化程序，没有风险回应和判断过程，事后很难证明勤勉尽责。

#### 5. 责任链例子：关联方资金占用

场景：上市公司控股股东通过供应商和客户绕道占用资金，年报未充分披露。

责任链可以这样分析：

```text
事实：异常资金往来、供应商客户关系异常、期后回款异常。
风险：关联方未识别，非经营性资金占用未披露，财务报表和信息披露重大遗漏。
规则：公司治理和信息披露要求、关联方审计准则、审计证据要求。
证据：银行流水、工商信息、函证、访谈、合同、资金闭环测试。
判断：是否存在隐性关联方或资金占用，披露是否完整。
结论：要求调整或披露；证据不足时考虑审计意见和证券服务责任风险。
```

这比背一堆条款更能指导实务。

### 记忆辅助

#### 责任分析表

| 问题 | 说明 |
|---|---|
| 谁 | 责任主体是谁 |
| 负什么责 | 法定或职业义务是什么 |
| 怎么违反 | 哪些事实表明可能违反 |
| 后果如何 | 对报表、披露、报告或赔偿有什么影响 |
| 如何证明 | 底稿和证据如何支持勤勉尽责 |

#### 口诀

责任先找人，再看义务；  
事实定违反，证据定抗辩；  
底稿不留痕，勤勉难证明。

#### 管理层责任 vs 注册会计师责任

| 项目 | 管理层 | 注册会计师 |
|---|---|---|
| 核心责任 | 编制财务报表 | 审计并发表意见 |
| 主要依据 | 会计准则、法律法规 | 审计准则、职业道德 |
| 不能做什么 | 提供虚假资料、隐瞒重大事项 | 机械接受管理层解释、证据不足仍签发 |
| 责任抗辩 | 如实编报和披露 | 证明按准则勤勉尽责 |

### 本章小结

1. 法律责任学习要围绕责任主体、义务、违反方式、后果和证据。
2. 管理层责任和注册会计师责任不同，但会在同一错报事项上交汇。
3. 勤勉尽责需要底稿证明，不是口头态度。
4. 证券服务责任尤其强调公众公司项目中的证据链和信息披露一致性。
5. 法律责任课程必须和会计判断、审计证据联动。

### 知识检测

2. [ ] 勤勉尽责需要通过审计程序和底稿证据体现。  
3. [ ] 法律责任分析应先识别责任主体。

## 第7章：案例表达模板

### 学习目标

- [ ] 掌握“场景 -> 关键事实 -> 风险 -> 规则 -> 程序 -> 证据 -> 判断 -> 结论 -> 复盘”的案例表达模板。
- [ ] 能把复杂案例写成清晰、可复核的判断过程。
- [ ] 能区分案例中的事实、争议、规则和结论。
- [ ] 能在案例中同时呈现会计、审计、法律和职业道德影响。
- [ ] 能用模板复盘后续课程中的专题案例。

### 核心内容

#### 1. 为什么需要案例表达模板

很多学习者不是不懂某个知识点，而是不会把知识点用在案例里。

案例通常不会整齐地告诉你“本题考收入确认”“本题考合并范围”。它会给出杂乱事实：合同、交易背景、管理层解释、资金流、会议记录、补充协议、审计证据、期后变化。

模板的作用，是让你在混乱事实中形成稳定表达。

#### 2. 标准模板

推荐模板是：

```text
场景
  -> 关键事实
  -> 主要争议
  -> 重大错报风险或责任风险
  -> 适用规则
  -> 应执行程序
  -> 已有证据和证据缺口
  -> 判断过程
  -> 结论
  -> 可复用经验
```

#### 3. 每一部分怎么写

**场景**写业务背景，不写结论。  
例如：“A 公司向海外客户销售定制化设备，并提供现场安装调试服务。”

**关键事实**写影响判断的事实。  
例如合同约定、交付条件、验收条件、付款安排、补充协议、期后情况。

**主要争议**写真正要判断的问题。  
例如“供货和调试是否构成两个单项履约义务”“发货时是否已经转移控制权”。

**风险**写错在哪里。  
例如提前确认收入、合同资产列报错误、应收账款减值不足、披露不完整。

**规则**写适用的会计准则、审计准则、法律或职业道德要求。  
不要只写编号，要写规则含义。

**程序**写注册会计师该做什么。  
例如检查合同和补充协议、访谈业务人员、检查发货验收、函证客户、检查期后回款和退货。

**证据缺口**写现有证据为什么不够。  
例如只有发货记录，没有客户验收；只有管理层说明，没有客户确认；只有估值报告，没有参数来源。

**判断过程**写条件如何满足或不满足。  
这是案例的核心，不能省略。

**结论**写会计处理、审计程序、报告或责任影响。

**复盘**写下次遇到类似场景可以复用什么经验。

#### 4. 迷你示范：海外定制设备收入

场景：A 公司向海外客户销售定制化设备，并约定提供现场调试服务。年末设备已出口，现场调试尚未完成。管理层认为已报关出口，可以确认全部收入。

关键事实：

- 产品为定制化设备；
- 合同约定现场调试后客户验收；
- 尾款与最终验收相关；
- 年末仅完成出口；
- 现场调试可能影响设备核心功能。

主要争议：

- 设备供货和调试是否可明确区分；
- 出口时客户是否取得控制权；
- 是否可以确认全部收入。

风险：

- 收入提前确认；
- 合同资产或应收账款列报错误；
- 期后退货或验收失败导致收入转回；
- 若为上市公司，可能涉及信息披露风险。

规则：

- 收入确认核心是客户取得控制权；
- 多项履约义务需要判断是否可明确区分；
- 如果调试是设备达到合同功能的关键步骤，供货和调试可能不是可分离履约义务。

程序：

- 检查主合同和补充协议；
- 检查贸易术语、货权转移、验收条款；
- 获取报关、提单、签收资料；
- 了解调试对设备功能的重要性；
- 函证或访谈客户；
- 检查期后调试、验收和回款。

证据缺口：

- 如果只有报关资料，没有客户验收或控制权转移证据，不能直接支持全部收入确认。

判断：

- 若调试是设备可使用的关键步骤，客户在年末可能尚未取得控制权；
- 若供货本身可独立受益，调试只是附带服务，则可能分拆确认，但需证据支持。

结论：

- 不能仅凭报关出口确认全部收入；
- 应根据履约义务拆分和控制权转移证据确定收入金额和时点；
- 证据不足时应追加程序，必要时要求调整。

复盘：

- 出口不是收入确认的充分条件；
- 定制化产品要重点关注调试、验收和尾款安排；
- 补充协议要结合实际履行验证。

4. 复盘能把一次案例变成可迁移经验。
5. 后续所有专题课程都应使用本章模板。

## 课程总复习

### 核心知识地图

```text
注册会计师执业判断
  -> 事实
      -> 合同、交易、资金流、组织架构、沟通记录
  -> 风险
      -> 重大错报、舞弊、披露遗漏、独立性威胁、责任风险
  -> 规则
      -> 会计准则、审计准则、法律、职业道德、政策监管
  -> 证据
      -> 外部证据、内部证据、直接证据、专家证据、期后证据
  -> 判断
      -> 条件是否满足、证据是否充分、错报是否重大
  -> 结论
      -> 会计处理、审计程序、报告意见、责任评价、复盘经验
```

### 易混概念总对比

| 概念A | 概念B | 核心区别 |

| 证据 | 结论 | 证据支持判断，结论是判断结果 |
| 会计判断 | 审计判断 | 前者看报表表达，后者看证据能否支撑报表 |
