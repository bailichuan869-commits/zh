# Python 第 14 课：Skill 是什么，以及如何安装和编写

## 今天把经验沉淀下来

前面我们已经做过 PDF 工具、Excel 操作、小工具 EXE 和 GUI 工具箱。

做到这里，大家会遇到一个很现实的问题：

> 每次让 AI 改项目，都要把项目规则、文件结构、命名习惯、注意事项重新说一遍。

说一两次还可以。

项目一复杂，就会变成：

- 这次忘了提醒它不要覆盖原文件。
- 下次忘了提醒它输出异常清单。
- 再下一次它又把代码写回一个大文件里。
- 换一个项目，又要从头解释一遍。

所以 AI 编程不能只靠临时提示词。

我们需要把稳定的经验沉淀成一套可复用的规则。

这就是 Skill 要解决的问题。

## Skill 是什么

Skill 可以理解为：

> 给 AI 准备的一套可复用能力包。

它不是一个神奇插件，也不是让 AI 突然拥有超能力。

更准确地说，Skill 是一份结构化说明：

- 什么时候应该使用这个能力。
- 这个场景应该按什么流程做。
- 输入文件通常是什么。
- 输出结果应该长什么样。
- 有哪些安全规则不能违反。
- 有没有脚本、模板、示例可以复用。

以前我们是每次临时告诉 AI：

> 帮我处理这个 Excel，注意不要覆盖原文件，输出到 output，异常数据单独列出来。

有了 Skill 以后，我们可以把这套规则写成长期说明。

以后遇到类似任务，AI 就可以按同一套工作流来处理。

## Prompt、README、Instruction、Skill 的区别

这几个东西很容易混在一起。

可以先用一张表理解：

| 名称 | 主要作用 | 使用范围 |
|---|---|---|
| Prompt | 一次性任务指令 | 当前这一次对话 |
| README | 项目说明书 | 给人看，也给 AI 理解项目 |
| Instruction | 当前项目的长期规则 | 这个项目里长期生效 |
| Skill | 可复用的能力包 | 可以迁移到多个项目 |

Prompt 更像今天要做什么。

README 更像这个项目是什么。

Instruction 更像在这个项目里做事的规矩。

Skill 更像一套可以反复调用的方法。

举个例子：

```text
Prompt：
帮我把这个 Excel 清洗一下。

README：
这个项目是一个财务数据处理工具箱。

Instruction：
本项目所有输出文件都放到 output 目录，不能覆盖原始数据。

Skill：
当用户要求做 Excel 字段标准化时，按字段映射表读取、清洗、校验、输出异常清单。
```

## Skill 里通常有什么

一个最小 Skill 通常至少有一个 `SKILL.md`。

复杂一点的 Skill 还会带脚本、模板和参考资料。

```text
excel-field-standardizer/
  SKILL.md
  templates/
    field_mapping.json
  references/
    sample_columns.md
  scripts/
    validate_columns.py
```

其中最重要的是 `SKILL.md`。

它负责告诉 AI：

- 这个 Skill 什么时候使用。
- 使用前要先确认什么。
- 操作步骤是什么。
- 输出结果应该是什么。
- 哪些事情不能做。

`templates` 用来放模板。

`references` 用来放参考规则。

`scripts` 用来放可以重复执行的小脚本。

不是每个 Skill 都必须有这些目录。

但 `SKILL.md` 一定要写清楚。

## 为什么需要 Skill

Skill 的价值，不是让 AI 少问你一句话。

它真正的价值是：

> 把一次成功经验，变成以后可以复用的工作流。

在真实项目里，很多事情不是一次性任务。

比如：

- 每个月都要清洗一批 Excel。
- 每次新增工具都要登记到工具注册表。
- 每次打包前都要检查 README、依赖和输出目录。
- 每次处理 Word 都要保留原文件，输出一个新文件。

这些规则如果只写在聊天里，很快就会丢。

写成 Skill，就可以变成项目能力的一部分。

## 如何安装 Skill

不同 AI 编程工具对 Skill 的叫法和目录不完全一样。

所以这节课不要求大家死记某一个命令。

先理解本质：

> 安装 Skill，就是把一个包含 `SKILL.md` 的文件夹，放到 AI 工具能够识别的位置。

常见方式有三种。

第一种：复制文件夹。

别人给你一个 Skill 文件夹，你把它复制到工具支持的 skills 目录里。

第二种：从课程附件或 GitHub 获取。

Skill 本质上就是文件，所以可以通过压缩包、GitHub 仓库、课程附件分发。

第三种：使用工具自带的安装命令或插件市场。

有些 AI 编程工具会提供安装命令，有些会提供插件市场。

但无论界面怎么变，本质都是一样的：

```text
找到 Skill
复制或安装到指定位置
重启或刷新 AI 工具
在任务中触发它
```

## 安装后怎么判断它有没有用上

不要只看有没有复制成功。

要看 AI 做事方式有没有变化。

可以这样测试：

```text
我这里有一个 Excel 字段标准化任务。
请判断是否应该使用已有的 Excel 字段标准化 Skill。
如果应该使用，请先说明你会按 Skill 中的哪些规则执行。
```

如果 AI 能说出 Skill 里的规则，说明它大概率读到了。

如果它完全不知道，就要检查：

- Skill 放的位置对不对。
- 文件夹里是否有 `SKILL.md`。
- 当前工具是否支持读取这个位置。
- 是否需要重启或刷新。
- 触发描述是否太模糊。

## 如何写一个最小 Skill

通常直接说出自己的需求或者结合之前的上下文

使用skill creator 让AI帮忙写Skill即可

## Skill 写得好不好，看三件事

第一，触发场景是否清楚。

AI 要知道什么时候该用它。

第二，步骤是否稳定。

不要只写一句“帮我处理好”，而要写清楚先做什么、后做什么。

第三，边界是否明确。

尤其是文件处理类任务，一定要写清楚：

- 不覆盖原文件。
- 输出到指定目录。
- 出错时不要静默跳过。
- 重要操作前先确认。

Skill 不是写得越长越好。

能稳定指导 AI 做事，才是好 Skill。

## 今天的课堂练习

今天不急着做复杂安装。

我们先把前面课程里已经形成的经验，整理成一个 Skill 草稿。

场景选择：

> Excel 字段标准化和数据清洗。

目标是让大家理解：

- Skill 不是玄学。
- Skill 是经验沉淀。
- Skill 可以让 AI 从“临时干活”变成“按流程干活”。

## 本节课案例提示词

```text
我正在学习 AI 编程里的 Skill。

请你用适合初学者的方式，帮我完成三件事：

1. 解释 Skill 是什么，并对比 prompt、README、instruction、Skill 的区别。
2. 设计一个名为 excel-field-standardizer 的 Skill，用来处理 Excel 字段标准化和数据清洗。
3. 输出这个 Skill 的目录结构，并写出完整的 SKILL.md 内容。

要求：
- 触发场景要清楚。
- 输入和输出要明确。
- 操作步骤要按真实工作流排列。
- 安全规则里必须包含不覆盖原文件、输出到 output 目录、生成异常清单。
- 语言要适合给非程序员理解。
```

## 这节课学完以后

大家不需要马上写出很复杂的 Skill。

只要先记住一句话：

> Prompt 解决这一次，Skill 沉淀下一次。

AI 编程不是每次重新许愿。

越往后做，越要把稳定规则、项目经验和业务流程沉淀下来。
