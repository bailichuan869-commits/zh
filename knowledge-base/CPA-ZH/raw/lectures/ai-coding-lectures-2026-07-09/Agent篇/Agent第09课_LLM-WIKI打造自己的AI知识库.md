# Agent第09课：LLM WIKI 打造自己的 AI 知识库

## 这一节要解决什么

上一节课，我们已经做了一个最朴素的本地知识库：

```text
一个文件夹 + 一批 Markdown 文档。
```

这种方式很容易理解。

把资料交给 Agent，让它整理成 `.md` 文件，再放到对应分类里。

当知识库只有几篇文档时，这种方式已经很好用。

比如你问：

```text
根据知识库里的内容，告诉我如何蒸馏一个人的思维方式。
```

Agent 可以在文件夹里搜索相关文档，读取内容，然后总结给你。

但这一节要继续往前走一步。

因为真实知识库不会永远只有几篇文档。

当资料变成几十篇、几百篇、甚至几千篇时，只靠“把 Markdown 堆进文件夹”，就会遇到问题。

这一节要解决的问题是：

```text
怎样让知识库不只是堆文件，而是变成一个 AI 更容易理解和检索的知识网络？
```

课程里用到的方法是：

```text
LLM WIKI。
```

它的核心思想是：

```text
把原始资料保留下来，再让 AI 把资料编译成索引、概念、实体、摘要和知识链接。
```

这样以后再提问时，Agent 不用每次都在大量原文里盲目搜索，而是可以先看索引和知识结构，再去定位真正需要的内容。

## 普通知识库的问题

上一节课的知识库，本质上是一个普通文件夹。

里面可能有：

- 公众号文章总结；
- 网页资料整理；
- PDF 问询函摘要；
- 自己的学习笔记；
- 课程讲义；
- 工作经验沉淀。

这种方式非常适合入门。

因为它简单、直观、没有复杂依赖。

但当资料越来越多时，会出现几个问题。

第一个问题是搜索范围太大。

如果文件夹里只有两三个文档，Agent 很容易找到相关内容。

但如果里面有 200 个文档、2000 个文档，Agent 每次都要先判断该读哪些文件。

这个过程会变慢。

第二个问题是容易找错资料。

很多知识之间会有相似关键词。

比如都提到“Excel”“Agent”“VBA”“AI 编程”，但它们实际讨论的主题可能完全不同。

Agent 如果只靠关键词搜索，就可能读到不够相关的文档。

第三个问题是消耗 Token。

Agent 每次回答问题，都要搜索、打开、读取、筛选。

文档越多，读取成本越高。

如果每次都重新读大量原文，就不适合长期使用。

第四个问题是缺少关系。

一个好的知识库，不只是“存放文件”。

它还应该知道：

- 哪些文档讲的是同一个主题；
- 哪些概念之间有关联；
- 哪些技术属于同一类；
- 哪些资料是源文件；
- 哪些内容是 AI 已经提炼过的知识卡片；
- 哪些材料需要以后继续补充。

这些关系如果都靠人手动维护，就会很痛苦。

传统知识库难坚持，很大一部分原因就是：

```text
人不喜欢长期做打标签、建索引、维护链接这种枯燥工作。
```

而这些事情，恰好适合交给 AI。

## 先认识 Obsidian

在进入 LLM WIKI 之前，课程里先介绍了一个工具：

```text
Obsidian。
```

Obsidian 是一个本地 Markdown 笔记软件。

官网地址：

[Obsidian - 磨砺你的思维](https://obsidian.md/zh/)

它可以理解为：

```text
一个更适合管理 Markdown 知识库的软件。
```

普通的文件夹也能放 Markdown。

VS Code 也能打开 Markdown。

但 Obsidian 对知识库更友好，因为它支持：

- Markdown 预览；
- 双向链接；
- 反向链接；
- 关系图谱；
- 画布；
- 本地仓库管理。

这里的“仓库”不用想复杂。

在 Obsidian 里，一个仓库本质上就是一个文件夹。

比如上一节课创建的：

```text
知识库
```

就可以直接用 Obsidian 打开。

打开以后，Obsidian 会在这个文件夹里生成一个隐藏配置目录，比如：

```text
.obsidian
```

如果用 WorkBuddy 或其他 Agent 操作过这个目录，也可能看到类似：

```text
.workbuddy
```

这类以点开头的文件夹一般是工具自己的配置文件。

学习阶段不需要重点看。

真正重要的是你自己的 Markdown 文档。

## Obsidian 的双向链接和图谱

Obsidian 最有代表性的能力，是双向链接。

假设当前有三篇笔记：

```text
AI知识库.md
Agent整理文章.md
财审案例.md
```

如果这些文档之间没有任何链接，Obsidian 的关系图谱里，它们就是三个互不相干的点。

如果想在一篇文档里链接另一篇文档，可以输入：

```text
[[文档名称]]
```

比如：

```text
[[Agent整理文章]]
```

这样，当前文档就和 `Agent整理文章.md` 建立了链接。

在 Obsidian 的图谱里，就能看到两个节点之间产生了关系。

点击这个链接，也可以直接跳转到对应文档。

这就是知识库里的“关系”。

不过这一节课不要求手动去维护大量链接。

我们只是先理解：

```text
一个成熟的知识库，不只是文件很多，而是文件之间有关系。
```

后面 LLM WIKI 要做的事情，就是让 AI 帮我们把这些关系整理出来。

## Obsidian 在本课中的作用

这一节课里，Obsidian 主要承担三个作用。

第一，用来查看 Markdown 文档。

AI 生成的知识库文件，本质上还是 `.md` 文件。

Obsidian 可以很舒服地打开和预览。

第二，用来查看知识之间的链接。

当 AI 编译出索引、概念、实体和来源摘要以后，这些页面之间会形成链接。

Obsidian 的图谱可以让你看到知识库从“几个孤立文件”慢慢变成“一个知识网络”。

第三，用来辅助理解知识库结构。

比如你看到 `index`、`overview`、`sources`、`entities`、`concepts` 这些目录或文件时，可以直接在 Obsidian 里点开查看。

但要注意：

```text
Obsidian 不是本节课的主角。
```

它更像是一个查看器和笔记管理工具。

真正负责整理知识、抽取概念、建立索引的是 Agent 和 LLM WIKI。

## LLM WIKI 的核心思想

LLM WIKI 的理念，可以简单理解成一句话：

```text
不要让 AI 每次都重新翻原始资料，而是先把资料编译成适合 AI 使用的知识库。
```

这里的“编译”，不是写程序时的编译。

可以把它理解为：

```text
把原始材料加工成结构化知识。
```

原始材料可能是：

- 课程讲义；
- 网页文章；
- PDF；
- 研究资料；
- 工作文档；
- 会议记录；
- 自己的笔记。

这些材料直接堆在文件夹里，当然也能用。

但 LLM WIKI 会进一步做几件事：

- 保留原始文件；
- 为每份资料生成摘要；
- 提取资料中的概念；
- 提取资料中的实体；
- 建立内容索引；
- 生成整体概览；
- 把相关页面链接起来；
- 记录知识库维护过程。

这样，知识库就不只是“资料仓库”。

它会变成一个 AI 可以顺着索引和链接查找的知识网络。

## 安装 LLM WIKI Skill

课程中使用的是一个 LLM WIKI Skill。

可以在 Skill 市场里搜索：

```text
wiki
```

找到对应的 LLM WIKI Skill 后，把安装提示复制到 Agent 里，让 Agent 帮你安装。

课程里是用 WorkBuddy 演示。

如果你使用的是别的 Agent，只要它支持 Skill 或类似的能力，也可以按对应方式安装。

安装完成后，Agent 就知道如何初始化和维护一个 LLM WIKI 知识库。

也就是说，以后你可以用自然语言告诉它：

```text
用 LLM WIKI 初始化这个仓库。
```

或者：

```text
把这里面的资料编译入库。
```

Agent 会按照 LLM WIKI 的规则去创建目录、整理原文、生成索引和更新知识页面。

## 初始化一个新的 wiki 仓库

安装好 Skill 后，可以先创建一个新的文件夹。

课程里示例叫：

```text
my wiki
```

你也可以叫：

```text
我的知识库
财审知识库
AI学习知识库
项目资料库
```

名字不重要。

关键是这个文件夹以后专门用来放 LLM WIKI 知识库。

然后在 Agent 里打开这个文件夹作为当前工作空间。

接着输入：

```text
用 LLM WIKI 初始化这个仓库。
```

Agent 会在这个文件夹里创建一套基础结构。

初始化完成后，你会看到一些新的文件和目录。

如果一开始看不懂，不用紧张。

这很正常。

可以直接问 Agent：

```text
我现在不太了解 wiki 的结构。
你用当前的知识库给我解释一下，结构中的每个部分意义是什么，以后我该如何使用？
```

Agent 自己知道这套结构的用途，也能结合当前文件夹给你解释。

## 初始化后会看到什么

LLM WIKI 初始化后，大体会分成几层。

第一层是原始文档层。

通常会有一个类似 `raw` 的目录。

`raw` 可以理解为：

```text
原始资料区。
```

这里保存的是原始文件。

原来的资料是什么样，放进去后就尽量保持什么样。

它的作用是溯源。

也就是说，后面如果你想知道某个知识点来自哪份原始资料，可以回到 `raw` 里查看。

这个区域一般不要让 AI 随便修改。

第二层是知识库层。

通常会有一个 `wiki` 目录。

这里才是 AI 主要维护的区域。

AI 会根据原始资料，在这里生成摘要、概念、实体、索引、概览等内容。

常见结构包括：

```text
sources
entities
concepts
index
overview
```

不同版本的 Skill 或不同知识库，目录名字可能略有差异。

但核心意思类似。

`sources` 用来记录每份来源资料的摘要。

比如你放入一批课程讲义，每一节课都可能生成一个来源摘要。

里面会记录：

- 这份资料的基本信息；
- 它讲了什么；
- 核心知识点是什么；
- 涉及哪些概念；
- 可以链接到哪些实体或主题。

`entities` 用来记录实体。

实体可以是比较具体的对象。

比如：

- 一个工具；
- 一个技术；
- 一个产品；
- 一个人物；
- 一个项目；
- 一个业务对象。

课程里演示的资料偏技术学习，所以实体可能会按“技术”维度来抽取。

如果你的知识库是财审领域，实体也可能是：

- 公司；
- 准则；
- 监管机构；
- 财务科目；
- 审计程序；
- 业务循环；
- 典型风险。

具体按什么维度抽取，可以由你告诉 Agent。

如果你暂时没有明确想法，也可以先让 AI 自己按它认为合理的方式抽取。

`concepts` 用来记录概念。

概念比实体更抽象。

比如：

- 双向链接；
- 知识图谱；
- 索引；
- 编译入库；
- Agent 工作空间；
- Markdown 知识库。

这些概念会帮助 AI 理解知识库里反复出现的主题。

`index` 是内容索引。

以后 Agent 想查某个问题时，可以先看索引。

比如你问的是 Excel 自动化相关内容。

Agent 可以先通过 `index` 判断：

```text
哪些来源资料可能与 Excel 自动化有关？
哪些概念页面需要读取？
哪些实体页面可能相关？
```

这样它不用在几百个原始文件中盲目翻找。

`overview` 是综合概览。

它告诉 AI：

```text
这个知识库整体收录了什么内容，核心主线是什么，模块之间是什么关系。
```

有了 `index` 和 `overview`，Agent 查询知识时会更有方向。

第三层是配置层。

比如可能会有类似：

```text
.wiki-schema.md
purpose.md
log.md
```

这些文件用来告诉 Agent：

- 当前知识库的结构是什么；
- 这个知识库的用途是什么；
- 新资料进来后应该怎么入库；
- 哪些规则需要遵守；
- 之前做过哪些整理和更新。

这相当于知识库自己的使用说明和维护记录。

## 用 Obsidian 打开新仓库

LLM WIKI 初始化完成后，可以用 Obsidian 打开这个文件夹。

大致操作是：

1. 打开 Obsidian。
2. 选择打开本地仓库。
3. 选择刚才创建的 `my wiki` 文件夹。
4. 在左侧文件树里查看目录结构。

打开后，你会看到 LLM WIKI 创建的文件和目录。

一开始内容可能还比较空。

比如 `index` 里还没有多少索引，`overview` 也没有真正的知识脉络。

这是正常的。

因为知识库刚初始化，还没有资料入库。

下一步就是把素材交给 Agent。

## 把资料编译入库

课程里拿一批 Python 课程讲义做演示。

假设这些资料已经下载到了本地某个文件夹。

你可以直接告诉 Agent：

```text
把这里面的资料编译入库。
```

这里的“编译入库”可以拆成两层意思。

第一，把原始资料保存到原始资料区。

也就是放到 `raw` 里，作为后续溯源使用。

第二，按照 LLM WIKI 的规则，把资料加工成 wiki 知识。

也就是生成：

- 来源摘要；
- 概念卡片；
- 实体卡片；
- 内容索引；
- 整体概览；
- 页面之间的链接。

这一步可能会花一点时间。

因为 Agent 不是简单复制文件，而是在理解资料、抽取结构、建立关联。

等待它完成即可。

## 编译完成后发生了什么

编译完成后，可以先看 `raw`。

这里应该能看到完整的原始 Markdown 或原始资料。

要记住：

```text
raw 是数据源。
```

它不是给 AI 随便改写的地方。

它的主要作用是保留原文、方便溯源。

然后再看 `wiki`。

这里会多出很多 AI 生成的页面。

比如每份课程资料的摘要、相关概念、具体实体、索引页面和总览页面。

这些页面不一定都适合像教材一样逐页阅读。

这一点很重要。

LLM WIKI 生成的很多内容，本质上是给 AI 用的。

它们像是知识库的地图、目录、索引和中间层。

人当然也可以看。

但它最重要的价值是：

```text
让 AI 下次回答问题时，不再盲目搜索原始文档，而是先沿着索引和概念去找。
```

如果索引里已经告诉它某个问题和哪几篇资料相关，它就可以更快定位。

如果索引还不够，它再回到 `raw` 里查原始资料。

这样就形成了一个更合理的查询路径：

```text
先看 overview 和 index
再看 concepts、entities、sources
必要时再回到 raw 查原文
```

## 为什么这比普通文件夹更适合长期使用

普通文件夹知识库的方式是：

```text
资料放进去，提问时再搜索原文。
```

LLM WIKI 的方式是：

```text
资料先入库，入库时就把索引、摘要、概念和链接建好。
```

前者适合小规模。

后者更适合长期积累。

当知识库越来越大时，LLM WIKI 的优势会越来越明显。

第一，查询更快。

Agent 不用每次从零开始找文件。

第二，定位更准。

因为概念、实体、来源之间已经建立了关系。

第三，更适合持续维护。

新资料进来后，AI 可以判断它和旧知识之间有什么关系。

比如：

- 是否涉及已有概念；
- 是否补充了某个实体；
- 是否和旧资料存在矛盾；
- 是否需要更新 overview；
- 是否需要增加新的索引入口。

第四，更容易形成知识图谱。

当页面之间建立链接后，Obsidian 的图谱会变得更有意义。

你能看到哪些主题是中心节点，哪些资料围绕某个概念展开，哪些知识还比较孤立。

## 这套方法也有成本

LLM WIKI 不是万能的。

它的好处很明显，但也有成本。

第一，入库更慢。

普通文件夹只要复制文件就可以。

LLM WIKI 需要阅读资料、抽取概念、生成页面、建立链接。

所以第一次编译会更耗时。

第二，需要理解结构。

你不需要一开始就完全掌握所有目录。

但至少要知道：

```text
raw 是原始资料，wiki 是 AI 维护的知识层。
```

否则后面看到很多自动生成的页面，会觉得混乱。

第三，需要定期检查质量。

AI 建的概念和链接不一定永远正确。

有些资料可能互相矛盾。

有些旧知识可能过时。

有些概念可能拆得太细或太粗。

所以后面可以让 Agent 定期做健康检查，比如：

```text
请检查当前知识库是否存在重复概念、相互矛盾的内容，或者需要合并的实体。
```

也可以问：

```text
当前知识库里哪些页面比较孤立，哪些主题还需要补充资料？
```

知识库不是一次性生成物。

它应该被持续维护。

## 怎么向自己的 wiki 提问

知识库编译完成后，就可以开始提问。

但提问方式可以比上一节更明确。

比如：

```text
根据当前 LLM WIKI 知识库，帮我总结 Python 学习路线。
```

或者：

```text
根据当前知识库，找出和 Excel 自动化相关的内容，并按学习顺序整理。
```

也可以问结构性问题：

```text
当前知识库有哪些核心主题？
```

```text
当前知识库里有哪些重要概念和实体？
```

```text
哪些内容已经整理得比较完整，哪些内容还比较薄弱？
```

还可以让它解释知识库本身：

```text
请解释当前知识库的目录结构，并告诉我以后新增资料应该怎么入库。
```

这类问题很适合在刚开始使用 LLM WIKI 时多问几次。

因为你需要先理解：

```text
自己的知识库是怎么组织的。
```

只有你心里有数，后面才知道该怎样给它补资料、改规则、查问题。

## 图谱的意义

当资料编译入库后，可以回到 Obsidian 看图谱。

这时图谱通常会比一开始丰富很多。

你会看到：

- `index` 连接到很多知识页面；
- 每份来源资料连接到相关概念；
- 概念之间可能互相关联；
- 实体页面和来源页面之间有联系；
- 某些主题形成比较集中的节点群。

这说明知识库已经从简单文件夹，变成了有结构的知识网络。

图谱不是为了好看。

它真正的意义是：

```text
让你和 AI 都能看到知识之间的连接。
```

以后 Agent 查知识时，也可以借助这些链接更快定位内容。

## 原始资料和加工知识要分开

这一节最重要的一个概念，是把原始资料和加工后的知识分开。

原始资料放在：

```text
raw
```

加工后的知识放在：

```text
wiki
```

这样做有几个好处。

第一，方便溯源。

AI 生成的摘要或概念如果不确定，可以回到原文检查。

第二，方便更新。

以后如果原始资料增加或替换，可以重新让 AI 编译。

第三，减少混乱。

不要把原文、摘要、索引、概念卡片全部混在一个目录里。

混在一起之后，人和 AI 都会更难判断每个文件的角色。

第四，方便长期维护。

`raw` 像资料仓库。

`wiki` 像知识地图。

两者职责不同。

## 什么资料适合入库

LLM WIKI 适合处理需要长期复用的资料。

比如：

- 课程讲义；
- 技术文档；
- 工作方法论；
- 审计案例；
- 监管问询；
- 项目复盘；
- 读书笔记；
- 会议纪要；
- 研究报告；
- 自己反复会问的知识。

不太适合随手把所有东西都塞进去。

因为入库是有成本的。

如果某个资料只是看一眼就丢，不一定需要编译入库。

更适合入库的是：

```text
以后还会反复查询、组合、复用、更新的知识。
```

## 使用时要注意什么

第一，注意隐私。

如果资料里有客户信息、个人信息、未公开项目资料，不要随便交给不可信的 Agent 或外部服务处理。

本地知识库不代表一定安全。

关键还要看你使用的 Agent 会不会把内容发到云端模型。

第二，保留原始资料。

不要只看 AI 生成的摘要。

摘要是加工结果，原文才是最终依据。

第三，不要迷信自动分类。

AI 会帮你抽取概念和实体，但它不一定完全符合你的业务理解。

如果分类不对，可以直接告诉它调整。

比如：

```text
以后把这类资料归到“审计程序”，不要归到“财务分析”。
```

第四，不要一开始追求完美结构。

先让知识库跑起来。

有了第一批资料之后，再慢慢调整概念、实体和分类。

知识库结构是长出来的，不是一开始设计完美的。

## 本节课的完整流程

把这一节课串起来，流程是这样的：

1. 先理解上一节普通 Markdown 文件夹知识库的局限。
2. 安装 Obsidian，用它打开本地 Markdown 文件夹。
3. 了解 Obsidian 的双向链接和图谱。
4. 在 Skill 市场安装 LLM WIKI Skill。
5. 新建一个知识库文件夹，比如 `my wiki`。
6. 在 Agent 里打开这个文件夹。
7. 让 Agent 用 LLM WIKI 初始化仓库。
8. 用 Obsidian 打开初始化后的仓库。
9. 准备一批课程讲义或其它资料。
10. 让 Agent 把资料编译入库。
11. 检查 `raw` 里是否保留原始资料。
12. 检查 `wiki` 里是否生成摘要、概念、实体、索引和概览。
13. 询问 Agent 当前知识库结构如何使用。
14. 打开 Obsidian 图谱，观察知识之间的连接。
15. 后续继续把真正有价值的资料持续入库。

## 这一节和上一节的区别

上一节课的重点是：

```text
让 Agent 把资料整理成 Markdown 文件。
```

这一节课的重点是：

```text
让 Agent 把 Markdown 资料进一步编译成知识网络。
```

上一节是知识库的雏形。

这一节是知识库的结构化升级。

可以这样理解：

```text
普通文件夹知识库：先有文档。
LLM WIKI 知识库：在文档之上，再建立索引、概念、实体和链接。
```

如果你只是临时整理几篇文章，用上一节的方法就够了。

如果你想长期维护一个自己的专业知识库，LLM WIKI 这种方式就更值得尝试。

## 本节记住这些就够了

第一，普通 Markdown 文件夹适合入门，但资料多了以后会遇到搜索慢、找不准、Token 消耗高的问题。

第二，Obsidian 可以打开本地 Markdown 文件夹，并通过双向链接和图谱展示知识关系。

第三，LLM WIKI 的核心是把原始资料编译成适合 AI 查询的知识结构。

第四，`raw` 是原始资料区，主要用于保留原文和溯源。

第五，`wiki` 是 AI 维护的知识层，里面会生成摘要、概念、实体、索引和概览。

第六，`index` 和 `overview` 能帮助 Agent 更快理解知识库里有什么。

第七，新资料入库时，AI 会尝试把它和已有概念、实体、来源页面建立链接。

第八，LLM WIKI 不是一次性工具，它更适合长期维护、持续补充、定期检查。

## 课后练习

自己新建一个文件夹：

```text
my wiki
```

在 Agent 里打开这个文件夹，然后输入：

```text
用 LLM WIKI 初始化这个仓库。
```

初始化完成后，用 Obsidian 打开这个文件夹，先观察有哪些目录和文件。

接着准备一批资料。

如果手边没有合适资料，可以直接用本课程已有的讲义。

然后对 Agent 说：

```text
把这里面的资料编译入库。
```

等待完成后，检查三件事：

- `raw` 里是否保留了原始资料；
- `wiki` 里是否生成了摘要、概念、实体、索引和概览；
- Obsidian 图谱里是否出现了页面之间的链接。

最后再问 Agent：

```text
请解释当前知识库的结构，以及以后我应该怎样继续往里面添加资料。
```

这一步做完，你就真正跑通了一次 LLM WIKI 知识库的完整流程。
