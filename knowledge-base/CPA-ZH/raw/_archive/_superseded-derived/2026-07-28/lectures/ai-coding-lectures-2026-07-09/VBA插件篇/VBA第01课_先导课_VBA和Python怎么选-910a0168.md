# 先导课：VBA 和 Python 怎么选

## 先把工具边界讲清楚

AI 可以帮我们写 VBA，也可以帮我们写 Python。

但这不代表所有问题都应该用同一种工具解决。

今天这节课先解决一个更重要的问题：

> 面对一个 Excel、财务或审计自动化场景，我们到底应该让 AI 写 VBA，还是写 Python？

## 先记住一句话

如果你的工作主要发生在 Excel 里面，并且主要与Excel进行交互，优先考虑 VBA。

如果你的工作已经超出单个 Excel，涉及批量文件、数据库、接口、系统化工具，优先考虑 Python。

## 两者的核心区别

| 对比项     | VBA                  | Python                        |
| ------- | -------------------- | ----------------------------- |
| 运行位置    | Excel 里面             | Excel 外面，作为独立程序运行             |
| 最适合     | 操作当前工作簿、格式、选区、按钮、加载宏 | 批量处理文件、数据分析、数据库、API、GUI、自动化项目 |
| 用户入口    | Excel 按钮、宏、加载项       | 命令行、桌面软件、网页、本地服务              |
| 上手成本    | 对 Excel 用户更直观        | 对项目化开发更友好                     |
| 部署方式    | `.xlsm`、`.xlam` 加载宏  | Python 项目、可执行程序、工具箱           |
| 典型风险    | 容易直接改坏当前 Excel       | 环境、依赖、路径、项目结构                 |
| 适合做大项目吗 | 不太适合长期堆复杂系统          | 更适合长期维护和扩展                    |

## 什么时候优先用 VBA

### 1. 操作对象就是当前 Excel

比如：

- 当前表去空行。
- 当前选区去空格。
- 当前工作簿生成目录。
- 当前报表一键格式化。
- 当前表高亮重复项。

这些动作就在 Excel 里完成，用 VBA 很自然。

### 2. 需要做成 Excel 按钮

如果你希望同事打开 Excel 后，直接点按钮完成操作：

- 清理数据。
- 格式化报表。
- 生成目录。
- 插入底稿索引。
- 高亮异常。

这类更适合做成 VBA 加载宏。

### 3. 强依赖 Excel 的界面和格式

比如：

- 冻结窗格。
- 设置筛选。
- 调整列宽。
- 设置颜色。
- 添加超链接。
- 插入批注。
- 操作当前选中区域。

这些是 Excel 自己的能力，VBA 调用起来更直接。

## 什么时候优先用 Python

### 1. 要处理很多文件

比如：

- 一个文件夹里几百个 Excel。
- 多个分公司 CSV 合并。
- 批量生成输出文件。
- 自动读取不同目录的数据。

Python 更适合这种批量处理和项目化组织。

### 2. 数据量比较大

如果数据量已经让 Excel 明显卡顿，或者需要更复杂的数据处理，Python 更合适。

比如：

- 大量序时账清洗。
- 多表关联。
- 大规模抽样。
- 复杂匹配。
- 数据库查询。

### 3. 需要连接外部系统

比如：

- 请求汇率 API。
- 查询企业信息接口。
- 调用 OCR、AI、Web 服务。
- 连接数据库。
- 做前后端页面。

这类已经不是 Excel 内部操作，Python 更自然。

### 4. 要做长期维护的软件项目

如果目标是一个持续扩展的工具箱：

- 有目录结构。
- 有模块。
- 有配置。
- 有日志。
- 有测试。
- 有数据库。
- 有 GUI。
- 有 Git 版本。

Python 更适合做项目底座。

## 两者都能做时怎么选

有些事情 VBA 和 Python 都能做。比如 Excel 清洗、合并、格式设置。

这时可以按下面几个问题判断。

## 选择问题 1：这个动作是不是主要发生在当前 Excel 里？

如果是，选 VBA。

例如：

- 当前选区去空格。
- 当前表设置格式。
- 当前工作簿生成目录。

如果不是，继续往下问。

## 选择问题 2：这个任务是不是要批量处理很多文件？

如果是，选 Python。

例如：

- 合并一个文件夹下所有 Excel。
- 批量读取客户底稿。
- 生成多个输出文件。

VBA 也能做，但项目变大后 Python 更稳。

## 选择问题 3：同事是不是只想在 Excel 里点按钮？

如果是，选 VBA 或 VBA 加载宏。

例如：

- 给审计同事装一个 Excel 插件。
- 打开 Excel 就能看到“审计工具箱”选项卡。

## 选择问题 4：是否需要日志、测试、数据库、接口、长期迭代？

如果是，选 Python。

这已经是软件项目，不只是一个 Excel 宏。

## 选择问题 5：是否非常依赖 Excel 格式和交互？

如果是，选 VBA。

比如：

- 保留当前格式。
- 操作选中区域。
- 处理筛选状态。
- 调整页面显示。
- 添加超链接和批注。

## 场景选择表

| 场景 | 推荐 | 原因 |
|---|---|---|
| 当前表删除空行 | VBA | 就在 Excel 内部操作，做成按钮方便 |
| 当前选区文本转数字 | VBA | 依赖选区，交互简单 |
| 当前报表一键美化 | VBA | 强依赖 Excel 格式 |
| 工作簿生成目录和超链接 | VBA | 操作 Sheet 和超链接很直接 |
| 高亮当前表重复项 | VBA | Excel 内部检查和标色方便 |
| 合并一个文件夹下几十个 Excel | Python | 批量文件处理更稳 |
| 清洗几十万行序时账 | Python | 数据量大，适合程序化处理 |
| 银行流水和账面双向匹配 | Python | 规则、日志、测试、输出更可控 |
| 费用异常检查并输出报告 | Python | 配置、日志、输出报告更适合项目化 |
| 调用汇率 API | Python | 网络请求和 JSON 处理更自然 |
| 建一个审计查询数据库 | Python | 数据库和 SQL 不是 VBA 强项 |
| 做一个 Excel 插件给同事点按钮 | VBA | 加载宏天然适合 Excel 用户 |
| 做一个长期扩展的审计工具箱 | Python | 项目结构、模块、测试、Git 更适合 |

## 两者可以配合吗

可以。

比较现实的组合是：

- VBA 做 Excel 内部入口和按钮。
- Python 做复杂数据处理。
- VBA 调用 Python 脚本，或者 Python 输出 Excel 结果再由 VBA 做格式和展示。

但初学阶段不要一上来就混用。

先记住：

- 小而贴近 Excel 的动作，用 VBA。
- 大而项目化的数据处理，用 Python。

## AI 时代真正要学的不是语法选择

我们不是为了学 VBA 而学 VBA，也不是为了学 Python 而学 Python。

我们真正要学的是：

- 看清业务场景。
- 选对工具边界。
- 把需求讲清楚。
- 让 AI 生成初版。
- 自己验证结果。
- 控制误操作风险。
- 把稳定能力沉淀成工具。

## 今天要记住

VBA 是 Excel 里的自动化按钮。

Python 是 Excel 外的项目化工具箱。

选工具时，先问：

> 这个问题主要发生在 Excel 里面，还是已经超出了 Excel？

## 做完以后你应该能

- 说清 VBA 和 Python 的主要区别。
- 判断一个自动化场景更适合哪种工具。
- 知道哪些任务可以先用 VBA，哪些任务应该直接走 Python。
- 理解为什么课程分成 Python 篇和 VBA 篇。
