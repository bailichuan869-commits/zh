# AI 编程与自动化风险控制清单

本页用于控制第五板块工具化落地风险。核心原则是：自动化可以处理重复动作和初步整理，但不能替代注册会计师的职业判断、审计结论和最终复核。

## 总体控制原则

| 原则 | 要求 |
|---|---|
| 原文不覆盖 | `raw/` 原始资料不得被自动化工具直接改写 |
| 输出可追溯 | 每次运行应留下输入、参数、时间、版本和输出路径 |
| 人工可复核 | 关键判断、异常处理和最终结论必须可人工打开核对 |
| 最小权限 | 工具只处理指定目录和文件，不默认扫描或修改无关路径 |
| 先备份后处理 | 对 Excel、Word、底稿目录做批量处理前，应生成备份或输出副本 |
| 明确失败状态 | 失败、跳过、异常和空结果应写入日志，不默默吞掉 |

## 输入控制

| 检查点 | 说明 |
|---|---|
| 文件范围 | 是否只处理指定目录、指定后缀、指定批次 |
| 文件完整性 | 是否记录文件大小、修改时间、哈希或版本 |
| 字段校验 | Excel/CSV 是否存在必要字段，字段名是否一致 |
| 日期口径 | 是否记录数据截止日、报告期、汇率日期或查询日期 |
| 来源可信度 | 外部数据、网页、API 是否记录来源和访问时间 |

## 处理控制

| 检查点 | 说明 |
|---|---|
| 规则透明 | 抽样、筛选、异常识别规则是否写在配置或说明中 |
| 可重复运行 | 同一输入和参数能否得到一致输出 |
| 异常记录 | 空文件、打不开、字段缺失、解析失败是否形成清单 |
| 人工确认 | 删除、覆盖、批量改名、断链、改公式前是否需要确认 |
| 版本隔离 | 新旧脚本、配置、模板是否能区分 |

## 输出控制

| 检查点 | 说明 |
|---|---|
| 输出不混同原文 | 处理结果应放到 output、processed 或 wiki 层，不覆盖 raw |
| 日志留痕 | 记录运行时间、输入数量、成功数量、失败数量 |
| 差异清单 | 对清洗、转换、替换类工具保留前后差异 |
| 复核入口 | 输出文件应有清晰的复核路径或索引 |
| 可回滚 | 批量改动应能通过备份或 Git 找回 |

## Agent 使用边界

| 类别 | 可以做 | 需要确认 | 不应直接做 |
|---|---|---|---|
| 知识库维护 | 读 raw、写 wiki、更新索引、跑体检 | 新增板块、批量改结构 | 删除原文、覆盖官方文件 |
| 底稿处理 | 生成清单、标记异常、辅助汇总 | 批量改名、断链、删除公式 | 改审计结论、替代复核签字 |
| 网页核验 | 打开页面、记录链接、保存标题 | 认定有效版本、替换来源入口 | 未核验即标记为官方有效 |
| 案例加工 | 提炼事实、规则、判断过程 | 形成最终口径 | 杜撰事实或准则依据 |

## VBA 加载项控制

| 风险 | 控制方式 |
|---|---|
| 误处理活动工作簿 | 执行前显示当前文件名和处理范围 |
| 批量删除或断链不可逆 | 默认另存副本，操作前二次确认 |
| 公式被替换为值 | 保留处理前备份，输出公式变更清单 |
| 团队版本不一致 | 加载项显示版本号和发布日期 |
| 宏安全风险 | 来源、用途和权限边界写入发布说明 |

## Python 工具控制

| 风险 | 控制方式 |
|---|---|
| 路径误选 | 使用显式参数或配置文件，输出前打印根路径 |
| 依赖漂移 | 统一使用 `.venv`，记录 requirements 或 pyproject |
| 批量覆盖 | 默认输出到新目录，覆盖需要显式参数 |
| 解析失败 | 捕获异常并写入失败清单 |
| 外部 API 不稳定 | 记录请求时间、参数和原始响应摘要 |

## 审计证据留痕

每个工具至少应保留：

1. 输入文件清单；
2. 工具版本或脚本路径；
3. 参数或配置；
4. 运行时间；
5. 输出文件；
6. 异常或跳过清单；
7. 人工复核记录。

## 上线前检查

| 问题 | 是/否 |
|---|---|
| 是否明确工具只辅助处理，不替代职业判断 |
| 是否有测试样例或小范围试运行结果 |
| 是否有备份或回滚方案 |
| 是否有日志和异常清单 |
| 是否写明输入字段和输出字段 |
| 是否回挂到对应审计场景或知识库页面 |
| 是否登记到 [[concepts/ai-coding-tool-registry]] |
| 是否通过 `tools/kb.py health` 或项目测试 |
