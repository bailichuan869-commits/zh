# Agent第04课：AI 写 HTML 幻灯片

## 今天先解决一个做课件的问题

前面我们已经讲过 Prompt、Skill、Agent，也做过一些工具类案例。

做到这里，大家会遇到一个很现实的问题：

> AI 能不能直接帮我们做一份课件？

很多同学第一反应可能是：

```text
让 AI 帮我生成 PPT。
```

这个方向当然可以。

但是实际用下来，会发现传统 PPT 有一个问题：

AI 很会写内容，也很会整理结构，但它对 PPT 里的排版、对齐、图片位置、字体层级，不一定稳定。

有时候生成出来的 PPT 看起来像是有内容，但打开以后会发现：

- 文字太满。
- 图片比例不对。
- 页面层次不清楚。
- 版式很像模板拼出来的。
- 想继续修改，还要回到 PowerPoint 里一点点调。

所以这节课我们换一个思路：

> 不让 AI 直接生成 PPT，而是让 AI 生成 HTML 幻灯片。

## HTML 幻灯片是什么

HTML 幻灯片，本质上就是一个网页。

它可以在浏览器里打开，也可以像 PPT 一样一页一页翻。

从形式上看，它像课件。

从技术上看，它是一个 HTML 文件，里面包含了：

- 页面结构。
- 样式。
- 图片。
- 动效。
- 翻页逻辑。
- 可能还有一些简单交互。

也就是说，HTML 幻灯片不是把 PPT 换了个后缀。

它更像是：

```text
用网页技术做出来的一份可播放课件。
```

这个方向对 AI 比较友好。

因为 HTML、CSS、JavaScript 本来就是文本，AI 很擅长生成和修改文本代码。

我们让 AI 写一段网页结构、调整一个样式、插入一张图片、增加一个章节页，通常比让 AI 精准操作 PPT 页面更自然。

## 为什么不是直接做 PPT

这里不是说 PPT 不好。

PPT 仍然是最常见、最稳妥的汇报工具。

尤其是正式汇报、客户沟通、团队协作、企业模板统一这些场景，PPT 依然很重要。

但是如果我们从 AI 生成的角度看，HTML 幻灯片有几个优势。

第一，结构更清楚。

HTML 里面有标题、段落、卡片、图片、列表、按钮、章节页，这些结构都可以用代码明确表达。

第二，样式更容易统一。

我们可以提前定义一套 CSS，让所有页面都遵守同一套字体、颜色、间距和布局规则。

第三，表现力更强。

网页里可以很自然地加入动效、背景、响应式布局、代码高亮、图片网格、数据大字报等效果。

第四，方便发布。

生成出来以后，可以是一个 HTML 文件，也可以部署成一个网页链接。

别人只要有浏览器，就能打开。

## 但 HTML 幻灯片也有问题

HTML 幻灯片最大的问题，不是生成。

而是最后修改。

PPT 的好处是大家都熟悉。

不管设计水平怎么样，至少能点一下文本框，改几个字，拖一下图片，调一下位置。

HTML 就不一样。

如果不会代码，看到一大段 HTML 和 CSS，很多人会直接放弃。

比如我们想做几个很简单的调整：

- 把标题字号调小一点。
- 把图片换成自己的截图。
- 把某一页的卡片往下挪一点。
- 把背景颜色改浅一点。
- 删除某个不需要的元素。

这些在 PPT 里是点几下的问题。

但在 HTML 里，可能就要找元素、找样式、改代码。

所以 HTML 幻灯片真正落地的难点，是最后一公里。

也就是：

> AI 已经生成了 80 分的课件，但最后那 20 分，怎么让普通用户也能改。

## Skill 在这里解决什么问题

如果只是临时对 AI 说：

```text
帮我做一个 HTML 幻灯片。
```

AI 也许能做出来。

但结果会不稳定。

这次可能是横向翻页。

下次可能是普通网页。

这次可能有章节页。

下次可能全是长段文字。

所以我们需要一个 Skill。

这里使用的是 `guizang-ppt-skill`。

它可以理解为：

> 一套专门指导 AI 生成 HTML 幻灯片的工作说明书。

这个 Skill 主要做几件事。

第一，规定输出形式。

生成的是横向翻页网页 PPT，通常是单个 HTML 文件。

第二，规定视觉风格。

它提供了几种相对稳定的风格模板，例如电子杂志风格、瑞士国际主义风格。

第三，规定页面组件。

例如封面页、章节页、数据页、图片网格、内容卡片、总结页。

第四，规定检查标准。

例如文字不能溢出，图片不能变形，页面翻页要正常，整体视觉要统一。

所以 Skill 的价值不是让 AI 更“神奇”。

它的价值是：

> 把做 HTML 幻灯片这件事，变成一套稳定可复用的工作流。

## 这个 Skill 里通常有什么

一个完整的 Skill，不只是一个提示词。

以这个 HTML 幻灯片 Skill 为例，通常会看到这些内容：

```text
guizang-ppt-skill/
  SKILL.md
  assets/
  references/
  scripts/
```

`SKILL.md` 是总说明书。

它告诉 AI：

- 什么时候应该使用这个 Skill。
- 生成什么类型的幻灯片。
- 应该遵守哪些页面规则。
- 输出时要注意什么。

`assets` 里通常放模板。

比如已经写好的 HTML 模板、CSS 样式、背景效果。

AI 生成时不是完全凭空写，而是参考这些模板来做。

`references` 里放参考规则。

比如图片提示词怎么写、截图怎么处理、页面检查清单是什么。

`scripts` 里可能放一些校验脚本。

例如检查生成的页面结构是否符合要求。

可以把它理解为：

```text
SKILL.md 负责告诉 AI 怎么做。
assets 负责提供模板。
references 负责提供细节标准。
scripts 负责帮助检查结果。
```

## 基本生成流程

这节课我们先跑通一个完整流程。

第一步，准备主题。

比如：

```text
我要做一份给审计人员看的 AI 知识库培训课件。
```

第二步，确定受众。

这一步很重要。

同样是 AI 知识库，给程序员讲和给审计项目组讲，页面内容和表达方式是不一样的。

可以这样说：

```text
受众是一线审计人员，不要求他们懂代码。
请用大白话解释概念，尽量用底稿、资料整理、项目经验沉淀这些场景举例。
```

第三步，确定风格。

如果是课程培训，可以选择干净、清晰、适合阅读的风格。

如果是作品展示，可以选择更有视觉冲击力的风格。

第四步，让 AI 使用 Skill 生成 HTML 幻灯片。

第五步，打开浏览器检查。

重点检查：

- 能不能正常翻页。
- 文字有没有超出页面。
- 图片是否正常显示。
- 页面风格是否统一。
- 内容是否符合课程逻辑。

第六步，进行最后调整。

如果只是小改，可以继续让 AI 改代码。

如果想像改 PPT 一样点选调整，可以使用 HTML 编辑器进行处理。

## 本节课演示提示词

可以先用下面这个提示词，让 AI 生成一份基础版本。

```text
请使用 guizang-ppt-skill，帮我生成一份横向翻页的 HTML 幻灯片。

主题：AI 知识库建设入门

受众：一线审计人员和财务人员，不要求懂代码。

课程目标：
1. 理解为什么需要个人知识库。
2. 理解普通文件夹、RAG 和 llm-wiki 这类知识库思路的区别。
3. 知道如何把项目经验、网页资料、公众号文章和本地文件整理成可复用知识。
4. 明白 AI 知识库不能替代专业判断，需要人工审核和持续维护。

页面要求：
- 生成单个 HTML 文件。
- 使用横向翻页形式。
- 风格干净、清晰，适合培训课件。
- 每页不要堆太多文字。
- 需要有封面页、问题页、方法页、流程页、案例页和总结页。
- 重要概念要用大白话解释。
- 不要使用敏感真实客户数据。
```

生成以后，不要马上认为它完成了。

要把它当成一个初稿。

和写文章一样，AI 生成的是第一版，我们还要检查、删减、补充和调整。

## 图片怎么处理

HTML 幻灯片里很适合放图片。

图片可以有三种来源。

第一种，使用自己的截图。

比如工具界面、操作步骤、文件目录、生成结果。

这种最适合教学，因为它是真实画面。

第二种，使用 AI 生成的信息图。

比如流程图、概念图、对比图。

这种适合解释抽象概念。

第三种，使用公开素材或自己制作的图标。

但要注意版权和风格统一。

如果使用生图模型，不要只说：

```text
生成一张 AI 知识库图片。
```

可以说得更具体一点：

```text
生成一张 16:9 的信息图，主题是“从零散资料到结构化知识库”。
画面左侧是零散的 PDF、网页、笔记和表格，中间是整理流程，右侧是结构化知识库和 AI 问答。
文字尽量少，风格干净，适合放在培训课件中。
```

图片生成以后，最好统一放到 `images` 文件夹里。

HTML 里用相对路径引用：

```html
<img src="images/wiki-flow.png" alt="知识库整理流程">
```

这样整个课件文件夹比较清楚，也方便以后移动和打包。

## 最后一公里：用 HTML 编辑器调整

HTML 幻灯片生成以后，最常见的问题是：

> 整体不错，但有些地方就是想手动调一下。

这时候如果直接改代码，对很多同学来说门槛比较高。

所以可以用 HTML 编辑器来做最后调整。

思路很简单：

```text
AI 负责生成初稿。
人负责判断内容。
编辑器负责做细节调整。
```

比如：

- 点选某个标题，调整字号。
- 点选某段文字，修改内容。
- 替换某张图片。
- 调整元素间距。
- 删除不需要的卡片。
- 修改颜色和背景。

这样就更接近大家熟悉的 PPT 修改方式。

也就是说，我们不是要求每个学员都学会写 HTML。

而是让大家知道：

> AI 生成 HTML 幻灯片以后，仍然可以通过工具继续加工。

## HTML 和 PPT 怎么选

这节课不是要证明 HTML 一定比 PPT 好。

更合理的判断是看场景。

如果是正式汇报、多人协作、客户现场使用、单位有固定模板，PPT 仍然是更稳妥的选择。

如果是个人录课、线上分享、工具介绍、技术说明、网页发布，HTML 幻灯片会更灵活。

可以简单这样理解：

| 场景          | 更适合      |
| ----------- | -------- |
| 客户正式汇报      | PPT      |
| 团队多人反复修改    | PPT      |
| 个人录课        | HTML 幻灯片 |
| AI 快速生成培训材料 | HTML 幻灯片 |
| 需要网页动效和交互   | HTML 幻灯片 |
| 要发给别人继续改    | PPT 更稳   |

所以不要把它们理解成替代关系。

它们更像两种不同工具。

PPT 适合成熟的办公流程。

HTML 幻灯片适合 AI 生成和网页表达。

## 使用时要注意什么

第一，不要把敏感资料直接交给 AI。

尤其是客户名称、合同、底稿、未公开财务数据，这些要先脱敏。

第二，不要完全相信 AI 写的专业内容。

AI 可以帮我们整理表达，但审计判断、会计判断、政策引用，还是要人工复核。

第三，不要为了好看牺牲清楚。

课件最重要的是让学员听懂。

动效、背景、图片，都是服务内容的。

第四，生成以后一定要自己打开检查。

HTML 文件不是生成出来就算完成。

至少要检查翻页、图片、文字溢出和整体逻辑。

## 课堂练习

这节课的练习不是让大家写复杂代码。

我们先完成一个最小闭环：

```text
主题输入
  ↓
AI 使用 Skill 生成 HTML 幻灯片
  ↓
浏览器打开检查
  ↓
补充图片
  ↓
用 HTML 编辑器做最后调整
  ↓
导出最终版本
```

练习主题可以选择：

```text
用 AI 做一个审计项目资料整理助手
```

要求：

- 至少 8 页。
- 有封面页和总结页。
- 至少包含一页流程图。
- 至少包含一页 HTML 和 PPT 的对比。
- 至少插入 2 张图片。
- 不使用真实客户资料。

## 本节课学完以后

大家不需要马上掌握 HTML、CSS 和 JavaScript。

这节课更重要的是理解一个新的工作流：

> AI 不一定只生成 PPT，也可以先生成 HTML 幻灯片。

Skill 负责把生成过程稳定下来。

浏览器负责展示。

图片模型负责补充视觉素材。

HTML 编辑器负责解决最后修改的问题。

最后还是人来判断内容是否准确、表达是否清楚、课件是否适合学员。

说到底，工具只是把门槛降下来。

真正决定课件质量的，还是我们对业务、受众和表达顺序的理解。
