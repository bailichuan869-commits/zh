# Agent第06课：这么多 Agent 到底怎么选

## 这一节要解决什么

现在 Agent 软件越来越多。

你可能听过：

- Claude Code；
- Codex；
- Cursor；
- Copilot；
- Kiro；
- OpenCode；
- OpenClaw；
- Hermes；
- Cherry Studio；
- 腾讯 WorkBuddy；
- 阿里 Qoder；
- Kimi Code；
- 智谱 ZCode；
- 字节 Trae Agent。

一眼看过去，名字很多，功能也都说得很强。

所以很多同学会卡在一个问题上：

```text
我到底该选哪个 Agent？
```

这一节不做软件排行榜。

因为 Agent 软件变化非常快，今天某个功能领先，过几个月可能大家都补上了。

这节课更重要的是建立一个判断框架：

> 不要被名字绕晕，先看它属于哪种形态，再看它适合哪种用途，最后再根据自己的模型套餐和使用门槛做选择。

本节内容基于课程录制时的观察，时间点是 `2026 年 7 月 5 日`。

以后产品名称、价格、模型版本、功能入口都可能变化，但这套选择方法仍然可以复用。

## 先不要纠结名字

不同厂商会给自己的能力起不同名字。

有的叫插件。

有的叫专家。

有的叫 Skill。

有的叫工具。

有的叫自动化任务。

但你把这些名字拆开看，本质上都差不多：

```text
给 Agent 增加能力，让它能在某个场景里做更多事情。
```

比如：

- 有的能力负责读写文件；
- 有的能力负责联网搜索；
- 有的能力负责操作浏览器；
- 有的能力负责处理 Excel；
- 有的能力负责执行某套固定流程；
- 有的能力负责连接微信、飞书、钉钉等外部软件。

所以学 Agent，不要先被产品名和功能名吓到。

先抓住底层逻辑：

```text
项目、会话、模型、工具、Skill、插件、记忆、外部软件连接。
```

不同产品只是把这些东西用不同界面包装起来。

## 按形态分：主要有三类 Agent

从使用形态看，现在常见的 Agent 大致可以分成三类。

第一类是 IDE 或代码编辑器内的 Agent。

第二类是终端或 CLI 形式的编程 Agent。

第三类是现代 Agent 控制台，也就是现在越来越常见的桌面端 Agent 软件。

这三类不是绝对隔离的。

很多产品已经开始互相学习，界面和功能也越来越像。

但按这三类理解，会更容易判断自己适合哪一种。

## 第一类：IDE 或编辑器内 Agent

这一类 Agent 是嵌在代码编辑器里的。

典型例子包括：

- Cursor；
- Copilot；
- Kiro；
- Trae。

它们的出发点是：

```text
帮程序员在写代码时更方便地使用 AI。
```

比如在 VS Code 里使用 Copilot，你可以一边看代码，一边和 AI 对话。

如果你想修改某一段代码，可以先选中那段代码，再让 AI 针对这段代码解释、修改、补全。

这种方式对写代码的人非常自然。

因为程序员本来就会盯着代码文件工作。

他们关心：

- 哪个函数写错了；
- 哪段代码要重新整理；
- 哪个变量要改名；
- 哪个文件要补测试；
- 哪个报错要定位。

编辑器内 Agent 的优势也在这里：

```text
它离代码最近。
```

但对大多数普通用户来说，这种形态不一定友好。

因为普通人并不关心代码怎么实现。

普通人更关心的是：

```text
我提出需求，最后能不能得到结果。
```

比如财审场景里，我们更关心：

- 能不能整理一份底稿；
- 能不能处理一个 Excel；
- 能不能生成一个工具；
- 能不能把资料分类；
- 能不能输出一份报告。

至于中间改了哪段代码、哪个函数、哪个文件，大部分人并不想看。

所以编辑器内 Agent 对程序员仍然很有价值，但它不是最适合所有人的形态。

## 第二类：终端或 CLI 编程 Agent

第二类是终端里的 Agent。

典型代表是：

- Claude Code；
- Codex CLI；
- OpenCode。

这一类产品刚出现时，很多人会觉得不理解。

因为它不是一个漂亮的软件界面，而是在终端黑框里对话。

用户需要在命令行里输入内容。

有些操作还需要记命令，比如：

- 进入项目目录；
- 恢复上一次会话；
- 开新会话；
- 切换上下文；
- 执行某些斜杠命令。

对熟悉终端的人来说，这很顺手。

因为开发者本来就在终端里运行项目、安装依赖、执行脚本、看报错。

终端 Agent 的优势是：

```text
直接、轻量、贴近工程环境。
```

它可以进入项目目录，读取文件，运行命令，修改代码。

但对普通用户来说，终端的心理门槛比较高。

很多人看到黑框就会紧张。

更不用说还要记一些命令。

所以这一类 Agent 更适合：

- 程序员；
- 熟悉命令行的人；
- 愿意折腾工具的人；
- 需要深度控制项目环境的人。

如果你只是想用 AI 完成日常办公、Excel、资料整理、自动化流程，终端不是最轻松的入口。

## 第三类：现代 Agent 控制台

现在越来越多产品都在走第三种形态：

```text
桌面端 Agent 控制台。
```

这一类软件通常会有一个独立客户端。

界面上常见的元素包括：

- 新建任务；
- 新建会话；
- 项目或空间；
- 选择文件夹；
- 选择模型；
- 历史会话；
- 插件；
- Skill；
- 专家；
- 自动化任务；
- 设置；
- 产物或输出文件。

课程中看到的 WorkBuddy、Codex、Kimi Code、Trae、Qoder 等，桌面端形态已经越来越接近。

你会发现它们大多都绕不开一个基本流程：

```text
选择一个文件夹作为项目
→ 在项目里新建会话
→ 给 Agent 提需求
→ Agent 在项目文件夹里读写文件、运行工具、交付结果
```

这对普通用户更友好。

因为它不像代码编辑器那样一打开就是代码，也不像终端那样需要敲命令。

它更像一个面向任务的工作台。

你只需要知道：

```text
我要让 AI 在哪个项目里干活。
```

然后把需求说清楚。

这也是为什么现在很多 Agent 产品都在往桌面端控制台靠拢。

## 为什么这些产品看起来越来越像

你把几个桌面端 Agent 打开，会发现它们的界面越来越像。

大概都有：

- 左侧任务或项目；
- 中间对话区；
- 文件夹或工作区；
- 模型选择；
- 插件或 Skill；
- 历史会话；
- 设置入口。

这是因为大家最终解决的是同一个问题：

```text
让大模型在一个真实项目环境里工作。
```

真实项目环境必须有几个东西。

第一，要有项目边界。

所以需要选择文件夹。

第二，要有对话上下文。

所以需要会话。

第三，要有模型。

所以需要选择或绑定模型。

第四，要有扩展能力。

所以需要插件、Skill、专家、MCP。

第五，要有结果交付。

所以需要文件、代码、报告、脚本、图片、网页等产物。

只要目标相同，产品形态自然会趋同。

所以不要在界面细节上消耗太多精力。

你真正要判断的是：

```text
哪个工具在你的网络环境、付费方式、模型选择、生态连接上更顺手。
```

## 按用途分：项目型 Agent 和个人助理型 Agent

除了按形态分，还可以按用途分。

课程里重点提到两条路线。

第一条路线是项目型 Agent。

第二条路线是个人助理型 Agent。

这两条路线的区别，比产品名字更重要。

## 项目型 Agent：进入一个项目，帮你解决问题

项目型 Agent 的代表包括：

- Codex；
- Kimi Code；
- Trae；
- Qoder；
- WorkBuddy；
- Claude Code。

它们的核心逻辑是：

```text
选择一个项目文件夹，让 Agent 进入这个项目里干活。
```

它更像一个项目协作者。

你给它一个具体目标，比如：

- 帮我整理一节课件；
- 帮我改一个 Excel 工具；
- 帮我写一个 VBA 加载项；
- 帮我生成一个 HTML 幻灯片；
- 帮我检查项目代码；
- 帮我把资料整理成 Markdown；
- 帮我处理某个文件夹里的数据。

它会围绕这个项目去工作。

项目型 Agent 适合解决明确任务。

它关注的是：

```text
这个项目里有什么文件？
用户想要交付什么结果？
我要调用哪些工具完成它？
```

所以对课程里的财审和办公自动化场景来说，项目型 Agent 很常用。

因为我们经常是围绕一个具体文件夹工作：

- 一个审计项目；
- 一套底稿；
- 一批 Excel；
- 一组课件；
- 一个 VBA 工具；
- 一个网页演示；
- 一个知识库目录。

这类任务都很适合用项目型 Agent。

## 个人助理型 Agent：围绕人和日常任务工作

另一条路线是个人助理型 Agent。

课程里以 Hermes、OpenClaw 这类产品为例。

它们的目标不只是进入一个项目文件夹，而是更像一个长期陪你工作的个人助理。

这类 Agent 往往会强调：

- 人格设置；
- 持久记忆；
- 你希望它怎么称呼你；
- 它应该用什么语气回复；
- 它擅长处理哪些日常任务；
- 它能不能接入飞书、微信、钉钉等消息平台；
- 它能不能从手机端接收任务，再在电脑端执行。

也就是说，个人助理型 Agent 更强调：

```text
它认识你，并且能长期配合你的工作习惯。
```

它适合处理一些持续性的、重复性的、跨软件的任务。

比如：

- 每天整理消息；
- 根据固定流程处理资料；
- 从飞书或微信里接收指令；
- 在电脑上执行后台任务；
- 维护个人知识库；
- 根据你的偏好输出内容；
- 帮你调用一组长期积累的 Skill。

这类 Agent 的方向很有想象力。

但它对配置能力、网络环境、模型设置、第三方软件连接的要求通常更高。

如果你愿意折腾，它很有潜力。

如果你只想立刻上手，可能项目型桌面 Agent 更稳。

## 项目型和个人助理型正在互相融合

需要注意的是，这两类产品并不是完全分开的。

它们正在互相学习。

项目型 Agent 开始加入：

- 记忆；
- 自定义指令；
- 个性化设置；
- 自动化任务；
- 手机端入口。

个人助理型 Agent 也开始加入：

- 项目文件夹；
- 桌面端控制台；
- 文件处理；
- 工具调用；
- 产物管理。

所以从最终形态看，大家会越来越像。

但从设计理念看，仍然有区别。

项目型 Agent 的第一目标是：

```text
进入一个项目，把任务交付出来。
```

个人助理型 Agent 的第一目标是：

```text
围绕一个人，长期处理他的日常任务。
```

选择时先看自己更需要哪一种。

## 选择 Agent 时看这几个维度

不要只问“哪个最强”。

更实用的问题是：

```text
哪个最适合我现在的使用条件？
```

可以从下面几个维度判断。

### 1. 安装和网络门槛

有些工具安装简单，下载客户端就能用。

有些工具需要额外网络环境、命令行安装、配置模型 Key、配置依赖。

如果你不想折腾，优先选低门槛的产品。

能稳定用起来，比理论上更强但装不上更重要。

### 2. 你已经买了什么模型套餐

很多 Agent 和模型是绑定的。

比如：

- Kimi 的 Agent 更适合搭配 Kimi 自己的模型；
- Codex 更鼓励使用 OpenAI 自家的模型；
- 某些国产 Agent 会鼓励你使用它自己的积分或模型；
- 有些开源工具可以接入多个模型，但配置更复杂。

所以最简单的原则是：

```text
你买了什么，就优先用它对应的 Agent。
```

如果你已经买了 Kimi 套餐，就先试 Kimi Code。

如果你已经买了 Trae 套餐，就先用 Trae。

如果你主要使用 OpenAI 模型，就优先考虑 Codex。

不要为了“换一个看起来更火的 Agent”，又额外付一份费用。

### 3. 是否需要自由选择模型

有些产品只能用自家模型。

优点是：

```text
集成简单，体验通常更顺。
```

缺点是：

```text
你不能随便切换到其他模型。
```

有些产品支持接入多家模型。

优点是：

```text
选择更自由，可以根据任务换模型。
```

缺点是：

```text
配置、计费、稳定性可能更复杂。
```

如果你是新手，不一定要追求“什么模型都能接”。

先把一个稳定工具用熟，价值更大。

### 4. 是否需要生态连接

有些 Agent 不只是做项目，还能连接外部软件。

比如：

- 微信；
- 企业微信；
- 飞书；
- 钉钉；
- 客服号；
- 小程序；
- 其他消息平台。

如果你的工作本身就在某个生态里，比如大量使用微信、企微、飞书，那支持这个生态的 Agent 会更方便。

课程里提到，腾讯系产品在连接微信、企微等生态上会有天然优势。

这类能力对个人助理型 Agent 很重要。

因为你可能希望：

```text
在手机上发一个任务，让电脑上的 Agent 去执行。
```

如果你没有这种需求，只是在电脑上处理项目文件，那生态连接就不是首要因素。

### 5. 插件、Skill 和工具生态

Agent 的能力不只取决于底层模型。

还取决于它能使用哪些工具。

有的产品插件多。

有的产品 Skill 市场丰富。

有的产品内置专家比较多。

有的产品 MCP 支持更成熟。

但这里也要注意：

```text
插件不是越多越好，够用、稳定、好理解更重要。
```

前面一节课我们已经看到，Skill 和插件太多，也会增加上下文成本和选择成本。

所以选择 Agent 时，不要只看插件数量。

要看你真正需要的场景有没有覆盖。

比如财审办公场景里，更需要关注：

- 能不能读写 Excel；
- 能不能处理 Word、PDF；
- 能不能访问本地文件；
- 能不能运行脚本；
- 能不能做浏览器自动化；
- 能不能稳定生成文档或课件；
- 能不能沉淀自己的工作流程。

### 6. 你喜欢哪种交互

有些人喜欢终端。

有些人喜欢编辑器。

有些人喜欢桌面客户端。

没有绝对正确。

关键是你愿不愿意长期使用。

一个工具再强，如果你每次打开都抗拒，那它对你就不是好工具。

对大多数非程序员来说，现代 Agent 控制台会更容易接受。

它把项目、会话、模型、插件都做成界面按钮，学习成本低一些。

## 一个简单选择建议

如果你不想折腾，也没有买其他模型套餐，可以先选择低门槛的国产桌面端 Agent。

课程里以腾讯 WorkBuddy 为例。

它的好处是：

- 安装和上手比较直接；
- 功能比较完整；
- 可以做项目任务；
- 也在吸收个人助理型 Agent 的能力；
- 对国内用户的网络和生态环境更友好；
- 可以连接腾讯自己的生态。

缺点是：

- 更依赖它自己的积分和模型体系；
- 不一定能自由选择所有模型；
- 费用规则要按平台当前政策看。

如果你已经买了某家模型套餐，就优先使用它对应的 Agent。

比如：

- 买了 Kimi，就先用 Kimi Code；
- 买了 Trae，就先用 Trae；
- 买了智谱，就先用 ZCode；
- 主要用 OpenAI，就先用 Codex；
- 熟悉命令行并且能稳定使用 Claude，就可以考虑 Claude Code。

如果你追求自由选择模型、个人助理、消息平台连接、长期记忆，可以研究 Hermes、OpenClaw 这类产品。

但这类工具通常需要更多配置，不建议把它作为所有人的第一入口。

## 不要为了选工具耽误开始

这一节最重要的结论是：

```text
不用过度纠结 Agent 名字。
```

因为现在各家的形态正在趋同。

你真正要学的是：

- 怎么选择项目；
- 怎么给 Agent 提需求；
- 怎么让它读文件；
- 怎么让它调用工具；
- 怎么检查它交付的结果；
- 怎么沉淀自己的 Skill；
- 怎么把 AI 融入实际工作流。

这些能力比“我到底装了哪个 Agent”更重要。

工具会变。

工作流会留下来。

## 本节记住这些就够了

第一，Agent 不要按名字记，要按形态和用途理解。

第二，常见形态有三类：编辑器内 Agent、终端 CLI Agent、桌面端 Agent 控制台。

第三，编辑器内 Agent 适合写代码的人，普通用户不一定需要盯着代码细节。

第四，终端 Agent 很强，但对普通用户有命令行门槛。

第五，桌面端 Agent 控制台更适合大多数办公、财审、项目处理场景。

第六，按用途看，可以分成项目型 Agent 和个人助理型 Agent。

第七，项目型 Agent 进入项目文件夹干活，个人助理型 Agent 围绕人和日常任务工作。

第八，最简单的选择原则是：你买了什么模型套餐，就先用对应 Agent；什么都没买，就先选低门槛、能稳定用起来的工具。

## 课后练习

打开你现在能使用的任意一个 Agent 工具，观察它的界面。

试着回答下面几个问题：

- 它有没有“项目”或“空间”的概念？
- 它是不是通过选择文件夹来确定工作范围？
- 它能不能新建会话？
- 它能不能选择模型？
- 它的插件、专家、Skill 或工具入口在哪里？
- 它更像项目型 Agent，还是个人助理型 Agent？
- 它适不适合你当前的工作场景？

做完这个练习后，你就不会只是在问“哪个 Agent 最强”。

你会开始问一个更实际的问题：

```text
哪个 Agent 能最低成本地进入我的工作流？
```
