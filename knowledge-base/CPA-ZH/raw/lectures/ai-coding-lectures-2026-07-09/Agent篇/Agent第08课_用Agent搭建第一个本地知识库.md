# Agent第08课：Agent 整理知识库（一）

## 这一节要解决什么

这一节开始，我们讲一个非常实用的方向：

```text
让 Agent 帮我们整理自己的知识库。
```

很多人一听“知识库”，会觉得它是一个很复杂的系统。

好像必须有数据库、向量检索、RAG、网页剪藏、自动同步、专业软件。

这些当然都可以做。

但这节课先不从复杂系统开始。

我们先从最朴素、最容易理解的方式开始：

> 让 AI 把各种信息源整理成 Markdown 文档，放进一个本地文件夹里。

这就是知识库的雏形。

## 知识库的本质

AI 帮我们搭知识库，本质上不是一件神秘的事。

它做的事情其实很简单：

```text
帮我们写文档。
```

前面学 Python、VBA、Agent 的时候，我们已经看到 AI 可以进入项目文件夹，帮我们写代码、改文件、生成课件。

写代码，本质上也是写文档。

只是这个文档里装的是代码。

整理知识库也是一样。

只不过这一次，文档里装的不是代码，而是：

- 文章总结；
- 资料摘要；
- 原文链接；
- 关键观点；
- 分类信息；
- 监管材料；
- 问询函要点；
- 自己以后要复用的知识。

所以最简单的知识库可以这样理解：

```text
一个文件夹 + 一批 Markdown 文档 + 一个清晰的分类结构。
```

这个结构既可以给人看，也可以给 AI 看。

这就是它的价值。

## 先创建一个知识库文件夹

第一步，先在本地创建一个文件夹。

名字可以很简单，比如：

```text
知识库
```

当然，文件夹名不重要。

你也可以叫：

- 我的知识库；
- 财审知识库；
- AI资料库；
- 学习笔记；
- 工作资料沉淀。

关键是：

```text
这个文件夹以后专门用来存放整理后的知识文档。
```

然后在 Agent 软件里打开这个文件夹。

课程里用的是 WorkBuddy 演示。

但原则上，使用哪一个 Agent 并不是最关键的。

只要这个 Agent 能打开本地文件夹、读写文件，就可以做类似的事情。

操作逻辑是：

1. 新建一个知识库文件夹。
2. 打开 Agent。
3. 选择空间或项目。
4. 打开本地文件夹。
5. 选择刚才创建的知识库目录。

这样，AI 就可以操作这个文件夹里的内容了。

## 信息源从哪里来

知识库不是凭空长出来的。

它需要信息源。

这一节课里，先用几个常见来源做演示：

- 公众号文章；
- 自己平时看到的资讯文章；
- 订阅来源；
- 监管网站；
- 巨潮资讯；
- 深交所、上交所的问询函；
- 在线 PDF 文档。

这些材料本来散落在不同地方。

平时我们可能只是收藏一下、转发一下、截图一下，然后就再也不会看。

知识库要做的事情，就是把这些零散材料整理成更稳定的文档。

可以这样理解：

```text
原始材料是输入，Markdown 文档是沉淀。
```

## 先让 AI 理解一篇文章

课程里先拿公众号文章做演示。

操作很简单。

先找到一篇公众号文章，复制文章链接。

然后把链接发给 Agent，让它先理解文章内容。

可以这样问：

```text
这篇文章写了什么？
```

这一步的目的不是马上建知识库。

而是先确认：

```text
AI 能不能读取这个信息源，并且把内容总结出来。
```

如果它能正常读取文章，就可以继续下一步。

如果它读取失败，可能需要换一种方式，比如复制正文、截图 OCR、网页解析、浏览器插件，或者让 Agent 使用其它工具。

## 再把总结落到本地文件夹

当 AI 已经能总结文章后，就可以让它把内容写进知识库文件夹。

示例指令：

```text
帮我整理到文件夹内，使用 MD 的格式。
```

这里的 `MD` 就是 Markdown。

Markdown 很适合做个人知识库。

因为它有几个优点：

- 本质是纯文本，稳定，不容易被软件绑定；
- AI 很擅长生成和修改 Markdown；
- VS Code、Obsidian 等软件都能打开；
- 标题、列表、引用、链接都很清晰；
- 后续也方便让 AI 再次读取和整理。

所以这一节先不追求复杂数据库。

先把知识沉淀成 `.md` 文件。

这一步跑通后，知识库就有了第一个文档。

## Agent 可能会生成自己的配置文件夹

课程里用 WorkBuddy 操作时，整理完第一篇文章后，除了生成 Markdown 文档，还出现了一个类似 `.workbuddy` 的文件夹。

这类文件夹一般是 Agent 软件自己的配置或记忆目录。

里面可能存放：

- 会话信息；
- 项目记忆；
- 当前任务记录；
- Agent 对这个空间的理解。

比如它可能会记录：

```text
今天抓取并整理了公众号文章，生成了某个 Markdown 文件。
```

这说明 Agent 不只是写了一个文档。

它也在慢慢理解：

```text
这个文件夹是用来做知识库整理的。
```

随着后续整理的材料越来越多，Agent 对这个项目的上下文也会更丰富。

但这类自动生成的配置目录，不一定需要手动修改。

只要知道它是 Agent 工作时产生的辅助文件即可。

## 知识库不能只是堆文件

如果只是把所有文章都扔进同一个文件夹，短期看没问题。

但内容一多，就会变成另一个杂物堆。

所以真正做知识库时，心里要有一个结构。

这节课先演示最基础的方式：

```text
按主题创建文件夹。
```

比如可以先创建几个分类：

- 财审知识；
- 审计技术；
- AI 技术；
- 生活技巧。

分类不需要一开始就非常完美。

先有一个大致结构就够了。

因为知识库会随着使用慢慢调整。

重要的是：

```text
不要让所有文档都挤在根目录里。
```

## 让 AI 根据文件夹结构自动分类

创建分类文件夹后，可以让 Agent 查看当前文件夹结构，并把文档移动到合适的位置。

示例指令：

```text
将这个文档移动到对应的分类中。
```

Agent 会尝试判断：

- 当前知识库里有哪些分类文件夹；
- 这篇文章属于哪个主题；
- 应该放到哪个目录。

但这里有一个小细节。

如果你是在 Agent 已经打开项目之后，才手动创建了新的文件夹，Agent 可能还不知道最新目录结构。

这时候可以提醒它：

```text
你看一下当前的文件夹。
```

让它重新读取目录。

课程中就出现了这个情况。

一开始 Agent 以为知识库里还没有分类结构。

提醒它重新查看文件夹后，它才发现已经有几个分类目录。

这说明：

> Agent 不是永远自动知道文件夹变化，必要时要提醒它重新观察当前环境。

## 分类不对时，可以直接纠正

AI 自动分类不一定一次就完全符合你的想法。

比如一篇文章既涉及财审，也涉及 AI。

Agent 可能会把它放进“审计技术”。

但你可能认为：

```text
这类文章更应该放在 AI 技术。
```

这时候不用纠结。

直接告诉它：

```text
这类文章放 AI 技术。
```

它就会按你的偏好调整。

这一步很重要。

因为知识库不是 AI 自己的知识库。

是你的知识库。

分类标准要逐渐贴合你的使用习惯。

AI 可以帮你判断，但最终结构应该由你来校准。

## 第二个例子：继续整理另一篇文章

当分类规则大致确定后，可以继续给 Agent 新的文章链接。

比如再给一篇和 Skill、AI 工具、财审结合相关的文章。

然后让它继续整理：

```text
把这篇文章整理到我的知识库。
```

这时 Agent 会根据已有目录和前面的偏好，自动判断放到哪里。

如果你之前告诉过它“这类文章放 AI 技术”，它后面就更可能把类似内容放进 `AI 技术` 目录。

整理后的 Markdown 文档里可以包含：

- 原文链接；
- 作者或来源；
- 文章主题；
- 内容摘要；
- 核心观点；
- 关键金句；
- 适合放入哪个分类；
- 对自己工作的启发。

这就是从“看过一篇文章”到“沉淀一条知识”的变化。

## 如果有自己的格式规范，要提前说清楚

这一节课里，先让 AI 自由整理。

它会自己决定标题、摘要、要点怎么写。

但如果你希望知识库长期可用，最好逐渐形成自己的格式规范。

比如每篇文档都包含：

- 标题；
- 来源；
- 原文链接；
- 整理日期；
- 主题分类；
- 适用场景；
- 核心观点；
- 关键摘录；
- 我的理解；
- 可复用动作；
- 相关链接。

如果有固定格式，就直接告诉 Agent：

```text
以后整理文章时，统一按这个格式写 Markdown：
标题、来源、原文链接、整理日期、分类、核心观点、关键内容、我的理解、可复用场景。
```

这样它后面整理出来的文档会更稳定。

知识库最怕的是每篇格式都不一样。

格式统一后，人看起来更舒服，AI 以后再读取也更容易。

## 第三个例子：整理监管问询函

除了公众号文章，这节课还演示了监管材料。

比如在监管动态、监管问询里找到一份问询函。

然后让 Agent 整理到知识库。

示例指令：

```text
将这个问询函也整理到我的知识库。
```

这类材料往往不是普通网页正文，而是在线 PDF。

Agent 可能会先做几件事：

1. 打开链接。
2. 下载 PDF。
3. 调用工具读取 PDF。
4. 提取 PDF 文本。
5. 总结问询函背景、问询要点和具体内容。
6. 写入知识库对应分类。

课程中，Agent 为了提取 PDF 内容，还安装了一个用于解析 PDF 的 Python 包。

这和前面 Python 课里讲过的逻辑是一样的：

```text
创建环境，安装工具包，读取文件，提取内容。
```

当然，如果你的 Agent 里已经有 PDF 相关 Skill，也可以让它使用现成 Skill。

不管底层用什么方式，最终目的都是：

```text
把 PDF 里的关键信息整理成可读、可检索、可复用的 Markdown 文档。
```

## 问询函适合怎么整理

财审场景里，问询函非常适合进入知识库。

因为它不是一次性材料。

后面做项目、看案例、写回复、分析监管关注点时，都可能再次用到。

一份问询函整理成 Markdown 时，可以包含：

- 公司名称；
- 所属板块；
- 问询背景；
- 问询问题；
- 监管关注点；
- 中介机构需要核查的事项；
- 涉及的会计、审计、内控问题；
- 可复用的回复思路；
- 对后续项目的启发；
- 原文 PDF 链接。

这样整理以后，它就不再只是一个下载过的 PDF。

它变成了可以复用的案例知识。

## 用 VS Code 或 Obsidian 查看

整理出来的 Markdown 文档，可以直接用 VS Code 打开。

课程里也提到，后面可以用 Obsidian 打开。

这一节先不深入讲 Obsidian。

你只需要先知道：

```text
Markdown 文件夹本身就是一个很好的知识库底座。
```

VS Code 更适合查看文件和编辑文本。

Obsidian 更适合做笔记、知识链接、双链和图谱。

后面如果要继续把知识库做得更像一个长期系统，就可以引入 Obsidian。

但第一步不用想太多。

先让 AI 把资料变成结构化 Markdown。

## 本节课的完整流程

把这一节课串起来，流程是这样的：

1. 创建一个本地知识库文件夹。
2. 在 Agent 里打开这个文件夹。
3. 找到一篇公众号文章或网页资料。
4. 复制链接给 Agent。
5. 让 Agent 总结文章内容。
6. 让 Agent 用 Markdown 格式写入知识库。
7. 创建基本分类文件夹。
8. 让 Agent 根据分类移动文档。
9. 如果分类不符合自己的理解，直接纠正。
10. 继续给 Agent 新的文章、PDF、问询函等素材。
11. 让 Agent 根据已有结构持续整理。

这个流程跑通以后，知识库就可以慢慢长起来。

## 不同信息源的处理方式

不同材料，处理方式会略有不同。

公众号文章：

通常可以先复制链接，让 Agent 尝试读取和总结。

普通网页资讯：

可以直接给链接，也可以配合浏览器接管能力读取页面。

监管网站：

适合让 Agent 读取网页内容，按监管主题或案例分类整理。

巨潮资讯：

适合整理公告、问询、回复、财务信息等材料。

PDF 文件：

可能需要先下载，再用 PDF 工具或 Python 包提取文本。

本地文件：

可以直接放到知识库文件夹或素材文件夹，让 Agent 读取并整理。

核心逻辑都是一样的：

```text
把来源交给 AI，让它理解、总结、分类、写入 Markdown。
```

## 这一节先不追求完美

这节课只是知识库整理的第一步。

现在先做到：

- 有一个文件夹；
- 有几个分类；
- 能把文章变成 Markdown；
- 能把 PDF 问询函变成总结文档；
- 能让 AI 根据结构写入对应位置。

这就够了。

后面再继续优化：

- 文件命名规则；
- 文档模板；
- 标签系统；
- 双向链接；
- Obsidian 展示；
- 自动化剪藏；
- 定期整理；
- 和 Agent 的长期记忆结合。

知识库不是一天建成的。

它是慢慢沉淀出来的。

## 本节记住这些就够了

第一，AI 整理知识库，本质上是帮我们写文档。

第二，最简单的知识库就是本地文件夹里的 Markdown 文档。

第三，Markdown 适合 AI 生成，也适合人阅读和后续维护。

第四，知识库不能只是堆文件，要有基本分类结构。

第五，Agent 可以读取当前文件夹结构，并把文档放到对应分类。

第六，AI 分类不对时，要直接纠正，让它逐渐贴合你的知识体系。

第七，公众号文章、网页资讯、监管材料、PDF 问询函，都可以成为知识库素材。

第八，这节课先搭雏形，下节课再继续讲如何用 Obsidian 等工具更好地浏览和管理。

## 课后练习

自己创建一个本地文件夹，命名为：

```text
我的知识库
```

然后在里面先建三个分类：

```text
AI技术
财审知识
生活技巧
```

找一篇你最近看过的文章，把链接发给 Agent。

让它先总结：

```text
这篇文章写了什么？
```

再让它落地：

```text
请把这篇文章整理到我的知识库中，使用 Markdown 格式，并根据当前文件夹结构放到合适分类。
```

最后检查两件事：

- 文件有没有生成；
- 分类是否符合你的理解。

如果分类不对，就直接告诉它：

```text
这类文章以后放到 AI技术。
```

这一步就是你开始训练自己知识库结构的起点。
