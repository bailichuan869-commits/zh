# Agent第05课：Agent 框架注入了什么内容

## 这一节要解决什么

前面几节课里，我们已经接触了 Agent、Skill、工具调用，也看到了 Agent 可以读文件、写代码、操作 Excel。

但是很多同学在真正使用 Agent 工具时，会遇到一个很奇怪的问题：

```text
我明明只发了一句“你好”，为什么消耗了几万 TOKEN？
```

这不是计费系统出错，也不是模型偷偷写了一篇文章。

真正的原因是：

> 你发给 Agent 的内容，不等于大模型最终看到的全部内容。

你输入的可能只有一句话。

但 Agent 框架在把请求发给大模型之前，会自动补充很多信息。

这些信息包括：

- 当前运行环境；
- 文件系统权限；
- 可用工具；
- 可用 Skill；
- 插件和 MCP；
- 当前工作区状态；
- Agent 应该怎么和用户协作；
- Agent 能做什么、不能做什么。

所以模型真正看到的，并不是孤零零的一句“你好”。

它看到的是一整包上下文。

这一节课，我们就借助一个请求观察工具，看一看 Agent 框架到底给大模型注入了哪些内容。

## 先理解一个关键点

普通聊天 AI 的使用方式比较简单。

你在网页里输入一句话，模型主要看到的就是：

```text
系统提示词 + 历史对话 + 你的最新问题
```

但 Agent 工具不一样。

Agent 不是只负责聊天。

它还要：

- 判断当前电脑环境；
- 知道自己有没有权限读写文件；
- 知道可以调用哪些工具；
- 知道哪些 Skill 可以用；
- 知道什么时候应该直接执行，什么时候应该询问用户；
- 知道怎样返回文件、图片、代码注释等结果。

这就决定了 Agent 每次请求大模型时，都需要带上大量“运行说明”。

这些说明对用户是隐藏的，但对模型是可见的。

所以我们看到的是：

```text
用户：你好
```

模型实际看到的更接近：

```text
你是某个 Agent 工具中的模型。
当前文件系统权限是……
当前可以使用的工具有……
当前可用的 Skill 有……
如果任务匹配某个 Skill，你应该……
如果用户让你处理图片，你应该……
如果用户让你操作文件，你应该……
当前协作模式是……
用户最新输入：你好
```

最后那句“你好”只是整个请求里的很小一部分。

## 用工具观察模型真正看到的内容

这一节课使用了一个开源的请求观察工具。

它的作用不是增强 Agent 能力，而是帮助我们看清楚：

> Agent 在调用大模型时，实际发出去了什么内容。

安装和启动方式可以按照项目说明操作。

大致流程是：

1. 使用 `uv tool install` 安装工具。
2. 根据自己使用的 Agent 软件选择对应的监控命令。
3. 启动监控面板。
4. 打开 Codex、Claude Code、Kimi、OpenCode 等 Agent 工具。
5. 发送一条简单消息，比如“你好”。
6. 回到监控面板查看这次请求的完整内容。

本节课里，我们观察的是 Codex。

当在 Codex 里输入“你好”之后，模型只是回复了一句普通问候。

但是请求观察工具里显示，这一次请求消耗了大约 `28,000` 个 TOKEN。

这就是问题的入口：

```text
为什么一句“你好”，会变成几万 TOKEN？
```

## “你好”在哪里

打开请求详情以后，会看到一大段内容。

这时候不要从上往下找用户输入。

因为用户真正输入的“你好”，通常在请求内容的最底部。

上面的大部分内容，都是 Agent 框架自动注入进去的。

也就是说：

```text
上面：Agent 框架注入的运行说明和环境信息
下面：用户真正输入的“你好”
```

这也是理解 Agent 的第一层变化：

> 在 Agent 场景里，用户输入只是上下文的一部分，不是全部上下文。

## Agent 框架主要注入了哪些内容

从这次观察来看，Agent 自动注入的内容大致可以分为几类。

### 1. 权限和运行环境

第一类是权限设置。

例如：

- 当前文件系统权限是什么；
- 是否允许读写本地文件；
- 网络访问是否可用；
- 命令行工具能不能执行；
- 是否需要额外授权；
- 当前命令执行时不能携带哪些特殊权限参数。

这类信息的作用是告诉模型：

```text
你现在处在什么环境里，可以做什么，不可以做什么。
```

如果没有这些信息，模型就不知道自己能不能读文件、能不能联网、能不能改项目、能不能运行命令。

对于普通网页聊天来说，这些内容可能不重要。

但对 Agent 来说非常重要。

因为 Agent 是要真正操作电脑和文件的。

### 2. 桌面端能力说明

第二类是 Codex 桌面端自身的能力说明。

例如：

- 可以使用 Markdown；
- 可以展示本地图片和视频；
- 引用本地文件时应该使用绝对路径；
- 处理图片时可以把图片展示给用户；
- 处理 Word、Excel、PPT、PDF 时可以加载工作区依赖；
- 如果用户要求创建提醒、定时任务、自动化，需要使用对应工具；
- 如果用户要求管理线程、归档线程、创建新线程，需要使用对应能力；
- 如果要对代码做行内反馈，可以使用规定格式。

这些内容本质上是在告诉模型：

```text
你不是在一个普通网页聊天框里，你是在 Codex 桌面应用里。
这个应用有一些特殊能力，你需要按它的规则来回复和操作。
```

这也是为什么同一个模型，在不同 Agent 软件里的表现会不一样。

底层模型可能类似，但外层框架给它注入的使用规则不同。

### 3. 工作区和会话状态

第三类是当前会话环境。

例如：

- 当前工作目录；
- 当前是否绑定了项目；
- 临时目录在哪里；
- 当前 shell 是什么；
- 当前有哪些工作区上下文。

这些信息会影响 Agent 的判断。

比如你让它：

```text
帮我整理这个字幕
```

如果 Agent 知道当前工作区在哪里，它就可以去目录里找文件。

如果它不知道工作区，就只能追问你文件在哪。

所以这些环境信息也是上下文的一部分。

### 4. 协作模式

第四类是协作模式。

比如本节观察到的默认模式，大意是：

```text
优先根据当前上下文直接行动，不要频繁向用户提问。
```

这类注入内容会影响 Agent 的做事风格。

有的模式会更偏“先问清楚”。

有的模式会更偏“先读代码、先执行、先推进”。

所以当你感觉一个 Agent 很主动，或者另一个 Agent 总爱问问题时，不一定只是模型性格不同，也可能是框架给它的协作规则不同。

### 5. Skill 路径和 Skill 列表

第五类，也是本节课里最值得注意的一类，是 Skill。

Agent 会把当前可用的 Skill 信息注入给模型。

这里通常包括两部分。

第一部分是 Skill 的存放路径。

它会告诉模型：

```text
哪些目录里可能存放 Skill 文件。
```

第二部分是当前可用的 Skill 列表。

每个 Skill 通常会包含：

- Skill 名称；
- Skill 描述；
- Skill 文件路径。

注意，这里通常不是把每个 Skill 的完整内容都塞进来。

它主要注入的是：

```text
名称 + 描述 + 路径
```

但是问题在于，如果你的 Skill 特别多，每个 Skill 哪怕只占一小段，几十个加起来也会很长。

本节课里观察到，Skill 列表占了很大一块上下文。

这就是一句“你好”也会消耗很多 TOKEN 的重要来源之一。

## 不要把 Skill 当收藏夹

很多人看到好用的 Skill，会有一个习惯：

```text
先装上再说。
```

这个习惯在普通软件里问题不大。

但在 Agent 里不太一样。

因为 Skill 不是安静地躺在硬盘里。

只要它处于可用状态，Agent 就可能在每次请求时把它的名称、描述、路径注入给模型。

这样会带来两个问题。

第一，占上下文。

Skill 越多，基础上下文越长。

即使你只是发一句“你好”，模型也要先读完这些可用 Skill 的说明。

第二，影响判断。

模型选择 Skill 的依据，正是这些名称和描述。

如果你装了很多相似的 Skill，比如三个都声称可以处理网页，两个都声称可以做 Excel，模型在选择时就可能犹豫，甚至选错。

所以 Skill 的管理原则应该是：

```text
常用的保留，不用的禁用，重复的合并，相似的精简。
```

Skill 不是越多越强。

对 Agent 来说，清晰比堆叠更重要。

## 6. Skill 使用规则

除了 Skill 列表，框架还会注入一段“如何使用 Skill”的规则。

例如：

- 如果用户明确点名某个 Skill，就必须使用；
- 如果任务明显匹配某个 Skill，也要使用；
- 如果多个 Skill 同时匹配，要按规则选择或组合；
- 使用 Skill 时，要先读取对应的 `SKILL.md`；
- 如果 Skill 里引用了脚本、模板、参考文件，要按路径继续读取；
- 如果有现成脚本，优先运行脚本，而不是重新手写一大段代码。

这段规则的意义是：

```text
告诉模型不要只知道“有哪些 Skill”，还要知道“怎样正确使用 Skill”。
```

这也是 Agent 和普通提示词的区别。

普通提示词更多是告诉模型“你要怎么回答”。

Agent 框架注入的规则，还会告诉模型“你要怎么工作”。

## 7. 插件和 MCP

继续往下看，还能看到插件系统和 MCP 的说明。

这类内容会告诉模型：

- 当前有哪些插件能力；
- 插件贡献了哪些 Skill；
- 插件贡献了哪些工具；
- MCP 工具应该怎样调用；
- 什么时候应该使用插件；
- 什么时候不要乱调用插件。

MCP 可以理解为一种把外部工具接入 Agent 的方式。

它让模型不只是生成文本，还可以通过工具去做事。

比如：

- 读本地文件；
- 查数据库；
- 操作浏览器；
- 调用 Excel 工具；
- 查询外部系统；
- 管理项目线程。

只要 Agent 框架允许模型调用这些能力，就需要在上下文里告诉模型：

```text
这些工具是什么，能做什么，应该怎么用。
```

这也会继续增加 TOKEN 消耗。

## 每一轮对话都会重新带上这些内容

还有一个容易忽略的点：

这些注入内容不是只在第一轮出现。

很多 Agent 工具在每一轮请求时，都会重新把框架规则、工具说明、Skill 列表、会话环境等内容带上。

比如第一轮你输入：

```text
你好
```

模型看到的是：

```text
大量框架上下文 + 用户输入：你好
```

第二轮你输入：

```text
把这些内容翻译出来
```

模型看到的也不是只有这句话。

它依然会看到：

```text
大量框架上下文 + 历史对话 + 用户新输入：把这些内容翻译出来
```

所以在 Agent 里，TOKEN 的消耗通常比普通网页聊天更高。

这不是因为 Agent “浪费”，而是因为 Agent 需要把工作环境一起交给模型。

## 这些注入内容有没有价值

有价值。

而且非常有价值。

如果没有这些内容，模型就很难像一个 Agent 一样工作。

它不知道：

- 当前能不能操作本地文件；
- 可以用哪些工具；
- 应该怎样调用工具；
- 当前有哪些 Skill；
- Skill 在什么情况下触发；
- 当前应用支持哪些特殊输出；
- 当前工作区在哪里；
- 应该主动推进，还是先问用户。

这些信息让模型从一个聊天助手，变成一个可以在真实环境里工作的 Agent。

所以我们不能简单地说：

```text
注入内容越少越好。
```

更准确的理解是：

```text
必要的上下文要保留，没用的上下文要清理。
```

## Agent 和网页聊天的本质区别

通过这一节课，可以更清楚地看到 Agent 和普通网页聊天的区别。

普通网页聊天更像：

```text
你问问题，模型回答。
```

Agent 更像：

```text
你提出目标，模型在一个带工具、带权限、带文件系统的环境里完成任务。
```

为了完成任务，模型必须先知道这个环境。

所以 Agent 框架才会注入大量内容。

这也是 Agent 能做更多事情的代价。

能力越多，说明越多。

工具越多，上下文越重。

Skill 越多，模型选择时需要读的内容也越多。

## 怎样减少不必要的 TOKEN 消耗

理解了注入内容以后，我们就可以做一些优化。

第一，清理不用的 Skill。

不用的 Skill 不要长期保持启用。

它不仅占上下文，还会增加模型选择成本。

第二，减少重复 Skill。

如果几个 Skill 功能非常接近，尽量保留最稳定、最常用的那个。

第三，不要把 Skill 当收藏夹。

看到有趣的 Skill 可以先记录下来，但不一定要全部装进当前 Agent 环境。

第四，按任务选择工作环境。

做 Excel，就保留 Excel 相关能力。

做网页，就保留浏览器和前端相关能力。

做写作，就保留文档和知识库相关能力。

第五，必要时开新会话。

当一个会话已经积累了很多历史上下文，又要开始一个新任务时，可以考虑新开一个会话，避免历史内容继续占用上下文。

第六，保持项目目录清晰。

Agent 会读取和理解当前工作区。

目录越清楚，文件命名越规范，模型越容易判断要处理什么。

## 可以观察不同 Agent 框架

本节课用请求观察工具观察了 Codex。

同样的方法也可以观察其他 Agent 工具。

例如：

- Claude Code；
- Kimi 相关 Agent；
- OpenCode；
- 其他支持命令行或桌面端的 Agent 工具。

不同工具注入的内容会不一样。

有的更强调命令行规则。

有的更强调项目上下文。

有的更强调工具调用。

有的会注入很多内置能力说明。

通过观察这些内容，可以反过来理解一个 Agent 框架的设计思路。

这比单纯看宣传页更直接。

因为你看到的是：

```text
模型真正拿到手里的工作说明书。
```

## 本节记住这些就够了

第一，用户输入不等于模型看到的全部内容。

第二，Agent 会在用户输入之前，自动注入大量框架上下文。

第三，一句“你好”消耗几万 TOKEN，主要是因为模型还读取了权限、环境、工具、Skill、插件、协作规则等内容。

第四，Skill 通常会以“名称 + 描述 + 路径”的形式注入给模型，数量多了也会占用很多上下文。

第五，Skill 不要当收藏夹，用不到的要禁用或清理。

第六，注入内容不是坏事，它是 Agent 能真正操作环境的前提。

第七，理解注入内容，可以帮助我们更好地理解 Agent 为什么这样回答、为什么这样行动、为什么会消耗这么多 TOKEN。

## 课后练习

可以自己做一个小实验。

先打开请求观察工具，然后在 Agent 里分别发送三类消息：

```text
你好
```

```text
帮我看一下当前目录有哪些文件
```

```text
帮我处理这个 Excel 文件
```

观察这三次请求里，模型看到的内容有什么变化。

重点看三件事：

- 用户输入在请求里的位置；
- Agent 框架自动注入了哪些内容；
- 哪些工具或 Skill 说明占用了比较多的 TOKEN。

做完这个练习后，你会更容易理解：

```text
Agent 不是一个更聪明的聊天框，而是一个带工作环境的执行系统。
```
