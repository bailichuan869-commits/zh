# VBA第08课：用下拉框保存状态

## 这一节要做什么

前面我们已经讲过按钮和菜单。

按钮适合“点一下就执行”的功能，菜单适合把多个按钮收起来。

这一节开始讲下拉框。

下拉框最常见的作用不是直接执行动作，而是让用户先选择一个状态或参数，再由其他按钮读取这个状态去执行。

本节案例是：

```text
新增一个“除以 X”下拉框
  ↓
提供“除以 1,000”和“除以 1 万”两个选项
  ↓
先尝试直接用下拉框触发动作
  ↓
发现重复选择同一项不会再次触发
  ↓
改成“下拉框保存状态 + 执行按钮读取状态”
```

## 本节你会学到

- 下拉框适合解决什么问题。
- 怎么给下拉框增加选项。
- 怎么把下拉框的选项传给 VBA。
- 为什么下拉框不适合作为“重复执行按钮”。
- 什么叫“状态选择器”。
- 怎么用一个按钮读取下拉框状态并执行操作。
- 什么时候应该用下拉框，什么时候应该直接用菜单按钮。

## 下拉框适合什么场景

如果一个功能需要参数，可以考虑下拉框。

例如：

- ROUND 保留几位小数：`2 位 / 3 位 / 4 位`
- 金额单位换算：`除以 1,000 / 除以 1 万`
- 处理范围：`当前选区 / 当前工作表 / 当前工作簿`
- 导出格式：`PDF / Excel / CSV`
- 风险等级：`高 / 中 / 低`

下拉框的价值在于：

> 用户先选一个状态，后面的按钮根据这个状态执行不同逻辑。

## 第一步：添加下拉框

打开之前的功能区设计器项目。

添加一个下拉框控件。

给它起一个名字，例如：

```text
除以 X
```

短提示可以写：

```text
将选中的单元格除以指定数值
```

给 AI 的功能说明可以先写：

```text
用户可以选择除以 1,000 或除以 1 万。
根据用户选择的选项，后续功能应使用对应的除数。
```

## 第二步：给下拉框增加选项

给下拉框添加两个选项：

```text
除以 1,000
除以 1 万
```

它们对应的含义是：

| 下拉选项 | 实际除数 |
| --- | --- |
| 除以 1,000 | 1000 |
| 除以 1 万 | 10000 |

这一步相当于把“参数”交给用户选择。

## 第三步：图标不一定适合下拉框

你可以尝试给下拉框配置图标。

例如去阿里巴巴矢量图标库搜索：

```text
单位换算
数学计算
除
office
```

下载 PNG 图标时，可以选择：

```text
64 x 64
```

不过实际预览时你可能会发现：

> 下拉框本身会占据显示区域，图标不一定能像按钮那样明显展示。

所以对下拉框来说，名称和选项往往比图标更重要。

图标可以有，但不必强求。

## 第四步：保存并导出设计

配置好下拉框后，先保存项目。

然后关闭 `final.xlsm`。

再点击：

```text
导出设计
```

导出后，设计器会把新的下拉框 XML 和回调 VBA 注入到：

```text
workbooks/final.xlsm
```

打开 `final.xlsm`，应该能在功能区里看到这个下拉框。

按：

```text
Alt + F11
```

进入 VBA 编辑器，也能看到设计器为这个下拉框生成的回调过程。

## 第五步：确认 AI 能看到这个控件

用 VS Code 打开项目根目录。

检查：

```text
CLAUDE.md
AGENTS.md
```

在功能清单里，应该能看到：

- 功能名称：除以 X；
- 控件类型：下拉框；
- 回调函数；
- 核心过程；
- 需求说明；
- 下拉选项。

只要这些信息存在，AI 就知道这个控件应该怎么处理。

## 第六步：第一次尝试，直接用下拉框执行

可以先让 AI 实现一个版本：

```text
实现“除以 X”功能。
用户选择“除以 1,000”时，将选中的单元格除以 1,000。
用户选择“除以 1 万”时，将选中的单元格除以 10,000。
先用 plan 模式确认实现计划。
```

AI 的计划通常会包括：

- 根据下拉项 ID 判断用户选择；
- 如果选择“除以 1,000”，除数就是 1000；
- 如果选择“除以 1 万”，除数就是 10000；
- 遍历当前选区；
- 跳过空单元格；
- 跳过非数字；
- 如果单元格是公式，就在公式基础上追加除法；
- 如果单元格是数值，就直接替换成换算后的数值；
- 注入并验证 `final.xlsm`。

确认计划没问题后，可以让 AI 执行。

## 第七步：测试直接触发的问题

打开 `final.xlsm`。

输入几个数字，例如：

```text
10000
100000
1000000
```

选择“除以 1 万”，你会看到它可以执行。

如果单元格是公式，例如：

```excel
=A1
```

执行后可能变成类似：

```excel
=A1/10000
```

这说明下拉框确实可以触发回调。

但这里会出现一个问题：

> 如果你已经选择了“除以 1,000”，再重新选择“除以 1,000”，它不会再次触发。

只有当你切换成另一个选项，例如从“除以 1,000”切到“除以 1 万”，才会触发。

## 为什么重复选择不会触发

这是下拉框的设计特点。

下拉框本质上是一个状态选择器。

它记录的是“当前选中了哪个状态”。

只有状态发生变化时，Excel 才会触发对应回调。

所以：

```text
从“除以 1,000”切换到“除以 1 万” → 状态变了，会触发
继续选择“除以 1,000”但原本就是“除以 1,000” → 状态没变，不触发
```

这不是 Bug，而是下拉框的正常逻辑。

## 正确用法：下拉框保存状态，按钮执行动作

更合理的设计是：

```text
下拉框：选择除数状态
按钮：读取当前状态并执行除法
```

也就是说：

1. 用户先在下拉框里选择“除以 1,000”或“除以 1 万”。
2. 下拉框把这个选择保存成一个状态。
3. 用户点击“执行除以 X”按钮。
4. 按钮读取刚才保存的状态，再处理选中的单元格。

这样就不会遇到“重复选择同一项不触发”的问题。

## 第八步：新增执行按钮

在设计器里新增一个按钮，例如：

```text
执行除以 X
```

给 AI 的功能说明可以写：

```text
根据“除以 X”下拉框当前保存的状态执行对应除法。
如果当前状态是“除以 1,000”，则将选中单元格除以 1,000。
如果当前状态是“除以 1 万”，则将选中单元格除以 10,000。
空单元格跳过。
非数字跳过。
如果单元格是公式，则在原公式基础上除以对应数值。
不要影响未选中的区域。
```

保存项目，关闭 `final.xlsm`，重新导出设计。

## 第九步：让 AI 按新逻辑实现

回到 AI 终端，可以这样说：

```text
我已经添加了“执行除以 X”按钮。
请按照“下拉框保存状态，按钮读取状态执行”的逻辑实现功能。
先给出 plan。
```

AI 应该会实现两部分逻辑：

### 下拉框选择过程

用户选择下拉项时，把对应除数保存到变量中。

例如：

```text
选择“除以 1,000” → 保存 1000
选择“除以 1 万” → 保存 10000
```

### 按钮执行过程

用户点击“执行除以 X”按钮时：

- 读取刚才保存的除数；
- 遍历当前选区；
- 空单元格跳过；
- 非数字跳过；
- 数值单元格直接除以对应除数；
- 公式单元格在公式基础上追加除法。

## 第十步：验证最终效果

打开 `final.xlsm`。

测试数值：

```text
10000
100000
```

先选择：

```text
除以 1 万
```

此时单元格不会立刻变化。

再点击：

```text
执行除以 X
```

单元格才会执行换算。

再测试：

```text
除以 1,000
```

然后点击执行按钮，确认结果正确。

这样下拉框就真正变成了“状态”，按钮变成了“动作”。

## 看一下 VBA 是怎么保存状态的

按：

```text
Alt + F11
```

进入 VBA 编辑器。

你通常会看到类似逻辑：

```vb
Private gDivideByValue As Double
```

这个变量用来保存当前选择的除数。

下拉框回调负责设置它：

```text
选择“除以 1,000” → gDivideByValue = 1000
选择“除以 1 万” → gDivideByValue = 10000
```

执行按钮负责读取它：

```text
读取 gDivideByValue → 对当前选区执行除法
```

这就是“用下拉框保存状态”的核心。

## 一个重要反思：这个案例适合下拉框吗

对于“除以 1,000 / 除以 1 万”这种只有两个动作的场景，其实直接用菜单可能更简单。

例如：

```text
单位换算
  除以 1,000
  除以 1 万
```

用户点哪个，就直接执行哪个。

这样比“先选下拉框，再点执行按钮”少一步。

所以这个案例更适合用来理解下拉框的机制，而不是说它一定是最佳界面设计。

下拉框更适合下面这种场景：

> 一个状态会影响多个按钮，或者一个参数会被多个功能共同使用。

比如：

```text
处理范围：当前选区 / 当前工作表 / 当前工作簿
```

然后下面很多按钮都读取这个范围状态。

再比如：

```text
输出单位：元 / 千元 / 万元
```

多个导出、格式化、换算按钮都读取这个单位状态。

这时下拉框就很有价值。

## 菜单里能不能放下拉框

实际测试时，你可能会发现：

> 菜单里面不一定适合放下拉框，很多情况下下拉框需要和按钮分开放。

菜单更适合收纳“动作按钮”。

下拉框更适合放在分组中，用来显示当前状态。

推荐结构：

```text
单位换算组
  下拉框：除以 X
  按钮：执行
```

或者：

```text
公式处理组
  下拉框：保留位数
  按钮：添加 ROUND
  按钮：添加 IFERROR
```

## 常见问题

### 为什么我选择同一个下拉项没有反应

因为下拉框只有在状态变化时才触发。

如果当前已经是这个选项，再选一次，状态没有变化，就不会触发。

### 下拉框能不能直接做功能按钮

能触发，但不推荐用于需要重复执行的动作。

更推荐：

```text
下拉框选参数
按钮执行动作
```

### 下拉框选项变了，但按钮执行不对

检查 VBA 中保存状态的变量是否被正确赋值。

也要检查按钮读取的是不是同一个变量。

### 两个选项而已，有必要用下拉框吗

不一定。

如果只有两个独立动作，菜单里放两个按钮可能更简单。

如果这个选项会影响多个按钮，下拉框就更合适。

## 本节记住这四点

1. 下拉框更像状态选择器，不是普通按钮。
2. 同一个选项重复选择时，通常不会再次触发。
3. 更稳的设计是“下拉框保存状态，按钮读取状态执行”。
4. 控件选择要看业务场景，不要为了用控件而用控件。
