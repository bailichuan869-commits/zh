# VBA第02课：初识 VBA 和加载宏按钮运行原理

## 这一节要解决什么

这一节我们先不急着正式开发加载项，而是先看懂 VBA 在哪里、代码怎么运行、Excel 加载宏上的按钮到底是怎样调用代码的。

你要先建立一个直觉：

> Excel 里的按钮不是魔法。你点击按钮以后，Excel 最终还是去运行了某一段 VBA 代码。

## 本节你会学到

- 怎么打开 VBA 编辑器。
- `.xlsm` 文件是什么意思。
- 普通 VBA 代码应该放在哪里。
- 怎么运行一行最简单的 VBA。
- Excel 功能区按钮是怎么显示出来的。
- `customUI.xml`、`onAction`、回调函数、真正业务函数之间是什么关系。

## 第一步：打开 VBA 编辑器

打开一个 Excel 工作簿，按：

```text
Alt + F11
```

这会打开 VBA 编辑器，也叫 VBE。

左侧可以看到当前工作簿的结构，例如：

- `Sheet1`
- `ThisWorkbook`
- 模块

如果是一个新的工作簿，一开始通常没有模块。

另外注意文件格式：

- `.xlsx`：普通工作簿，不能保存宏。
- `.xlsm`：启用宏的工作簿，可以保存 VBA 代码。

文件后缀里的 `m`，可以理解为 macro，也就是宏。

## 第二步：插入模块

在 VBA 编辑器左侧，右键当前工作簿：

```text
插入 → 模块
```

插入模块后，中间会出现一个可以写代码的区域。

普通宏代码一般先写在“模块”里，不要一开始就写到 `Sheet1` 或 `ThisWorkbook` 里面。

## 第三步：运行一行最简单的 VBA

在模块里输入：

```vb
Selection.Value = 111
```

回到 Excel，选中 `A1` 单元格。

再回到 VBA 编辑器，把光标放在这行代码上，点击运行按钮。

运行结果：

```text
A1 单元格被写入 111
```

这说明 VBA 可以直接感知你当前在 Excel 里选中了什么。

这里的 `Selection`，就是当前选中的区域。

这也是 VBA 的优势：它天然和当前 Excel 界面有交互。

## 加载宏按钮是怎么运行的

现在再看一个已经做好的加载宏按钮，例如“框线内虚外实”。

你在 Excel 中选中一片区域，点击这个按钮，选区的边框就被设置好了。

这个过程背后可以拆成三层：

```text
功能区按钮
  ↓
回调过程
  ↓
真正的业务代码
```

## 第一层：功能区按钮来自 XML

Excel 文件本质上可以看成一个压缩包。

如果把一个启用宏的 Excel 文件复制一份，把后缀改成 `.zip`，再解压，可能会看到：

```text
customUI/customUI.xml
```

这个 XML 文件会告诉 Excel：

- 要显示哪个选项卡；
- 选项卡下面有哪些组；
- 组里面有哪些按钮；
- 按钮显示什么文字；
- 鼠标放上去显示什么提示；
- 点击按钮以后要运行哪个回调过程。

一个功能区结构大概是这样：

```text
ribbon
  tab：底稿小帮手
    group：格式与打印相关
      button：框线内虚外实
```

对应到 XML 里，按钮可能长这样：

```xml
<button label="框线内虚外实" onAction="回调_框线内虚外实" />
```

这里最重要的是 `onAction`。

它的意思是：

> 当你点击这个按钮时，Excel 要去运行哪个 VBA 回调过程。

## 第二层：onAction 指向回调过程

假设 XML 里写的是：

```xml
onAction="回调_框线内虚外实"
```

那么 Excel 就会去 VBA 里找这个过程：

```vb
Sub 回调_框线内虚外实(control As IRibbonControl)
    Call 框线内虚外实
End Sub
```

这段代码就是回调过程。

回调过程通常不负责真正的业务，它更像是一个中转站。

## 第三层：回调过程调用真正业务代码

真正设置边框的代码，可能在另一个模块里：

```vb
Sub 框线内虚外实()
    ' 这里才是真正设置边框的代码
End Sub
```

所以完整流程是：

```text
点击按钮
  ↓
Excel 根据 customUI.xml 找到 onAction
  ↓
onAction 指向 VBA 回调过程
  ↓
回调过程 Call 真正业务函数
  ↓
真正业务函数修改 Excel
```

## 为什么要理解这个流程

后面我们会用功能区设计器来生成按钮和回调。

有了工具以后，你不用手写 XML，也不用手写一堆回调。

但是你仍然要知道：

- 按钮是怎么显示出来的；
- 按钮点击后去找谁；
- 回调函数为什么只是桥梁；
- 真正的功能代码应该写在哪里。

如果这条链路理解了，后面让 AI 帮你写加载项，就不会觉得黑箱。

## 本节记住这三句话

1. VBA 代码写在 VBA 编辑器里，普通宏先放在模块中。
2. Excel 功能区按钮是由 `customUI.xml` 描述出来的。
3. 按钮点击后，会通过 `onAction` 找到回调过程，再由回调过程调用真正业务代码。
